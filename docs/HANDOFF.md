## 0. いちばん大事なこと（必ず守る）

1. **オーナーは日本語で話す、エンジニアだけどこのコードは初めて見る人です。** 返事・計画・報告・コミットメッセージはすべて**日本語**で、専門用語を避けて、具体的に書いてください。
2. **作業の前に計画を説明して「OK」をもらう。** 作業の区切り（下の各段階）ごとに、「何を作るか・どう作るか・前の決定から変える所（理由）」を説明し、オーナーの OK を待ってから手を動かす。
3. **指示どおりにできなかった所・自分で判断した所は、必ず報告する。** 黙って仕様を変えない。できない時は「何ができないか・なぜか・代わりにどうしたか」を書く。
4. **終わったと言う前に、確認を全部通す**（§4）。テストが落ちたまま「完了」と言わない。失敗したら、失敗したと正直に書く。
5. **GitHub に push しない。** オーナーの GitHub アカウントは審査中。コミットだけして、区切りごとに bundle を作る（§5）。
6. **難易度は今のまま（難しめが良い）。** オーナーの方針。勝手にやさしくしない。数値を変える時は理由を書く。
7. **既存の動きを壊さない。** 変更のたびにテスト・型チェック・ビルドを通す。直す範囲は指示に必要な分だけにする。

## 1. ゲームの概要（前提）

- スマホ縦画面のブラウザで遊ぶ、1〜4人の協力ローグライトRPG。1回の冒険は60〜90分。
- 戦闘は「スロット判定 × デッキ構築」。カードごとに成功率があり、枠の成功数で効果が変わる。フォーカスを使うと枠を確定成功にできる。
- 世界マップ（霧・昼夜・侵食度・徘徊する敵・町・祠・ダンジョン）→ ダンジョン（部屋を選んで進む）→ 魔王城。
- 能力値は7つ: 力 str・体力 vit・知力 int・感知 per・器用 dex・素早さ agi・運 luk。「信仰」は無い。
- 協力: 1台を回して遊ぶ／各自のスマホでオンライン（Firebase）。キャラごとに場面が分かれる（ダンジョンと世界マップが同時に進む）。
- ジョブは44（基本8・中位13・最上位13・特殊10）。転職するとLv1に戻る。§6 と spec §6。

## 2. コードの地図

```
src/
  types/           型（index.ts = 戦闘・カード・ジョブ・お供、game.ts = 冒険・コマンド、world.ts = 世界マップ）
  content/         データ（ここにファイルを置くだけで登場する）
    common/        どのシナリオでも使う（classes・cards・items・enemies・statuses・elements・weaponTypes・pets・randomEvents …）
    scenarios/<id>/ シナリオ専用（map・dungeons・enemies・events・towns・shrines・quests）
  data/            登録表（import.meta.glob で content を集める）・balance.ts（数値はここ）
  engine/          ゲームの仕組み（純粋関数。画面から独立）
    battle/        戦闘（battle.ts・intents.ts・effects/kinds/ = 効果の部品）
    abilities/     特殊能力（conditions/ = 条件の部品）
    game/          冒険（game.ts = コマンドの入口、jobs.ts 転職、pets.ts お供、tasks.ts イベント後の作業、
                   cardTags.ts スマート抽選、outcomes/kinds/ = イベントの結果の部品、world/ = 世界マップ、migrations.ts 保存データの引き継ぎ）
    bot.ts         テスト用の自動プレイ
    __tests__/     テスト（vitest）
  store/           画面の状態（zustand。battleStore.ts がコマンドを送る・保存する）
  components/      画面（React）。battle/ 戦闘、screens/ 各画面、world/ 世界マップ、ui/ 共通部品
  art/ assets/art/ 絵（hero/<jobId>-<male|female>[-face].webp・enemy/<enemyId>.webp …）
scripts/           画面の自動確認（Playwright）・絵の加工（art/build_art.py）
```

### 仕組みの要点
- **コマンド**: 画面は `GameCommand`（types/game.ts）を送るだけ。`applyGameCommand(state, cmd)` が新しい状態を返す（structuredClone した上で変更）。
- **場面（scene）**: ダンジョンに入ったキャラは `game.expeditions` に分かれる。その中の操作は `{ type: 'SCENE', scene, command }` で包まれ、処理の間だけ `game.mode / dungeon / battle …` に載る（`engine/game/scenes.ts`）。**キャラがどこにいるか**は `heroPlace()`（jobs.ts）・`sceneOfHero()` を使う。
- **乱数**: `Rng`（seed から）だけ。`Math.random` は使わない（オンラインで全員の結果が同じでなくなる）。**乱数を引く順番を変えると、テストの自動プレイの流れが変わる**ことがある（§7）。
- **能力**（AbilityDef）: `{ when, if, do }`（きっかけ・条件・効果）か `{ modifier: 'damageDealt' | 'ignoreBlock' | 'coverLethal' | 'cardChance' | 'statusBonus' }`。`damageDealt` は `scale`（減ったHP・対象の状態異常の数・自分の状態異常）で増やせる。
- **きっかけ**: battleStart / turnStart / turnEnd / afterCard / perfect / kill / hurt。
- **キャラの能力の集め方**: `heroAbilities(hero)` = 持ち越した前のジョブの能力 ＋ 装備 ＋ お供。戦闘には `toPartyMember(hero)` で渡る。
- **カードの候補**: `heroCardPool(hero)` = 今のジョブ＋これまでのジョブの cardPool。報酬は `rollCardOffers`（3枚のうち2枚はスマート抽選、1枚は完全ランダム）。
- **イベント**: `EventDef`（where: dungeon / map / random）。選択肢の判定・お金・フォーカス・道具の支払い・結果（outcomes）。結果で戦闘を始める時は `event.battle` に入れて「戦闘を始める」で開始。
- **お供**: `hero.pet`。能力は PetDef の abilities / masterAbilities（獣使い系統）。表示は `components/ui/PetToken.tsx`。
- **保存データ**: localStorage。**型に任意の項目（?付き）を足すだけなら引き継ぎ不要**。項目の名前を変える・必須にする・意味を変える時は `GAME_VERSION`（= battle の STATE_VERSION）を1つ上げ、`migrations.ts` に直し方を1つ足す。

## 6. 品質の目安（ここまでのやり方）

### データ
- 能力は既存の部品を組み合わせて書く。足りなければ**部品を1ファイル足す**（条件・効果・結果）。ジョブIDで `if` 分岐しない。
- 説明文は `describeAbility` / `describeEffect` が自動で作る。不自然になる時だけ `description` を書く。
- カードの数値の目安（成功数0 / 1 / 2 の時）:
  - コスト1・2枠: 3 / 5〜6 / 7〜9 ダメージ（ブロックも同じくらい）
  - コスト2・2枠: 6 / 11〜12 / 16〜19
  - コスト3・3枠: 8〜10 / 14〜18 / 20〜26 / 28〜36
  - 全体攻撃は単体の5〜6割。状態異常は1〜2。コスト0は小さく。
- 新しいジョブの能力値は、元のジョブ＋得意な能力値に8〜10、最大HPは＋10前後。

### 画面
- スマホ縦（幅360〜480px）。文字は12px以上。押す所は高さ40px以上（44px推奨）。
- 色・ボタンは既存の部品（`btn btn-gold`・`btn btn-dark`・`panel`・`CardBody`・`HeroFace`・`PetToken`）を使う。
- 演出は短く（0.1〜0.4秒）。`prefers-reduced-motion` で止まるようにする。
- 協力プレイ: 他の人のキャラは操作できない（`isLocalPlayer`）。みんなで決める操作は投票（votes）。

### 言葉
- 画面の文言は、やさしい日本語で短く。英語の用語を出さない（例: ×「スロット」はOK（定着済み）、×「バフ」「デバフ」→「強化」「状態異常」）。
- 1行が長くなる時は、改行や箇条書きにする。

## 7. つまずきやすい所（実際に起きたこと）

- **乱数の順番が変わると、自動プレイのテストが別の流れになり、隠れていた不具合が出る。** 例: 突発イベントの判定で乱数を1つ多く引いたら、自動プレイが「手番でない人のキャラで宝箱を開けようとして止まる」問題が出た（bot 側を直した）。テストが落ちたら、まず「新しい変更の不具合か、乱数の流れが変わって出た古い問題か」を見分ける。
- **場面の分岐**: ダンジョンの中のキャラと世界マップのキャラで、`game.mode` の意味が違う。キャラの場所は `heroPlace` で判断する。
- **イベントの結果で場面を変えない**（結果を見せる前に戦闘になってしまう）。戦闘は `event.battle` に入れて、閉じる時に始める。お供・カード選び・行商人は、キャラの項目（petOffer / cardTask / peddler）に入れて、画面が落ち着いてから出す。
- **`BALANCE` は `as const`。** 数値を引数の既定値にすると型が固定値になる（`rareChance: number = BALANCE.x` のように型を書く）。
- **エピック以上のカード・装備には特殊能力が必須**（テストで落ちる）。
- **シナリオ専用の敵を共通のイベントで使わない**（他のシナリオで存在しない）。共通の敵を足す。
- **画面の確認スクリプトは文言で探して押す**。ボタンの文言を変えたらスクリプトも直す。新しい画面（重なる窓）を足すと、自動プレイがそこで止まることがある（adventure.mjs に扱いを足した例あり）。
- **Windows で作業する時**: 改行コードは LF のまま（`git config core.autocrlf false` を推奨）。パスは `/` で書く。
