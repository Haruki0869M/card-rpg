# シナリオ2「凍てつく王国」の作り直しの計画（2026-11-14・案）

オーナーの決定（11/14）「シナリオ2〜7を1本ずつ作り直す（地図・災厄・ダンジョン4か所をまとめて、1本ごとに遊んで確かめる）。シナリオ2から。難しさの調整は後でまとめて。災厄を6本に出すのは地図を広げる時に」を受けた、1本目の計画です。

- **コードは変えていません。** 書いてある数字・仕組みで、オーナーがまだ決めていない物は全部【提案】です。
- 「確かめた」= 今のコード・データを読んで確かめた事。「推測」= 読みからそう思うが、動かしていない事。重い測定・画面の確認は流していません。
- 憲章（`docs/CHARTER.md`）が基準。シナリオ1でできた形（広い地図・3つの道・災厄と加護・ランダムダンジョンと見破り・秘宝の3択・抜け道）を土台にし、**中身はシナリオ1の写しにしない**。

## 1. 今の姿と、憲章から見て足りない所

### 1-1. 「シナリオ2」はどれか（確かめた）

シナリオの並び（各 `scenario.ts` の `order`）: 1 侵食の魔王（corruptionKing）→ **2 凍てつく王国（frozenKingdom）** → 3 呪われた群島 → 4 砂の王朝 → 5 星降る天空城 → 6 機械仕掛けの帝国 → 7 夢の迷宮。
凍てつく王国は「侵食の魔王」をクリアすると遊べる。世界の悪化の名前は「冬の深さ」。遊びの違いは**寒さ**（雪原・氷原や寒い地域に立ったままワールドターンが終わるとHPが減る。野営で防げる。`src/engine/game/world/climate.ts`）。

### 1-3. 調べていて見つけた事（今のコード。確かめた）

1. **地平線の絵が、どのシナリオでも「魔王城」**（`LandscapeLayer.tsx:436` が `skyline-demon-castle` 決め打ち）。氷の城のシナリオで魔王城が見える。`skyline-snow-peak` はある。
2. **災厄の「悪さ」の文が「侵食度」と決め打ち**（`content/common/scourges/scourges.ts` の `curseShort: '侵食+0.5%'`・`curseText`）。シナリオ2では「冬の深さ」と出すべき。
3. **災厄を置く帯が `'west'` と `'east'` の決め打ち**（`engine/game/world/scourges.ts:80`）。帯の id を変えると災厄が置けない。
4. **災厄の種類はシナリオを見ない**（`SCOURGES.all` から選ぶ。手下は盗賊・沼の亡者・森の狼・火トカゲなど、シナリオ1の敵）。ただし「氷嵐の魔女」の手下（霜の狼・氷のコウモリ）は、もともとシナリオ2の敵。
5. **薬草の群生地のイベントの id が決め打ち**（`generate.ts:24 HERB_EVENT = 'herbField'`）。シナリオごとの「回復のマス」を置くには、地図のデータで選べるようにする必要がある。
6. 寒さの強さ: **雪原・氷原のマスは地形の寒さ（全体の 5%）が地域の寒さより優先**される（`climate.ts` の `climateAt`）。吹雪の山脈（地域 7%）では、平地や山の方が雪原より寒い。地図の注（「地域ぜんぶの寒さと雪原・氷原のマスで」）と食い違って見える。直すかは §6 の質問の外（難しさの調整の時に一緒に見る）。
7. 古い保存の決まり: 「広い地図」かどうかは、保存の地図の大きさがデータと同じかで決まる（`lanes.ts isWideMap`）。8×35 の保存は、帯・災厄・街道ボーナスを使わずに今までどおり遊べる。**マスは地域を番号（`tile.r`）で持つ**ので、地域の数と並びを変えると古い保存の地域がずれる。

## 2. 作る物（柱ごと）

### 2-1. 柱1 地図と3つの道（`frozenKingdom/map.ts`＋小さなエンジンの直し）

**地図【提案】**: 15列×42行。地域は**5つ・今の並びのまま**（古い保存のため。§2-7）、行だけ広げる（氷の城の荒野 0〜2／吹雪の山脈 3〜11／凍てついた湖 12〜24／白樺の雪林 25〜33／雪解けの麓 34〜41。シナリオ1と同じ行の幅）。徘徊する敵・宝箱・イベント・祠は今の約1.7倍（シナリオ1と同じ割合）。町・ダンジョン・歌碑は新しい座標へ（町は街道の上、鍵のダンジョンは街道から3〜5マスの脇道）。

**3つの道【提案】**（シナリオ1は「安全・速い・危険」。シナリオ2は**寒さ**を軸にして、別の悩みにする）:

| | ❄ 西「凍った湖の近道」 | 🔥 中央「薪の街道」 | ⛰ 東「巨人の尾根」 |
|---|---|---|---|
| 速さ | **速い**（新しい地形「湖の氷」= 移動力1。氷の上を滑る） | 街道 +1（今の街道ボーナス） | 遅い（山・森・丘） |
| 寒さ | **強い**（帯の寒さ ×2） | **弱い**（帯の寒さ ×0.5。番小屋の焚き火） | ふつう（×1） |
| 敵 | 少ない（湧く重み ×0.5） | 多い（×2.2。町が襲われる道） | ふつう（×1）・Lv+1（雪男・巨人の足跡） |
| 回復 | 無い | 町 | **温泉**（地図のイベント。全員回復＋その日の寒さを受けない）・祠 |
| 宝 | 湖底の沈んだ物（宝箱は少ないが、ランダムダンジョンの入口1つ） | — | 宝箱が多く良い（奥の重み2段）・祭壇 |
| 悩み | 「HPを削られても早く着くか」 | 「戦いが増えても暖かい道か」 | 「遅くて強い敵でも、宝と温泉を取りに行くか」 |

- 寒さとの関係: 地図が広がると寒い所を歩く時間が増える（推測: HPの減りが増える）。**難しさの調整は後でまとめて**なので、数字はこの表のまま測って記録だけする。

**エンジンの直し（小さい。シナリオ1の動きは変えない）**:
1. 帯の寒さの倍率 `LaneDef.climate`（省略 1）→ `climateAt` で掛ける。
2. 新しい地形「湖の氷」（`content/common/terrains/climate.ts`。移動力1・寒い）。データだけ。地図の色と模様は絵のセッション。
3. 薬草のイベントを地図で選べるように `ScenarioMapDef.herbEvent`（省略は今の `herbField`）。シナリオ2は新しい地図のイベント「温泉」（`where: 'map'`）。**温泉の役割**: 「HPの回復」と「その日の寒さを受けない」を1か所で。薬草（回復だけ）・焚き火の旅人（回復かフォーカス）と違う。
4. 盆地の中身に「イベント」（温泉）を足すか、`herbs` の帯（`prefer.herb: 'east'`）で済ませる → **`prefer.herb` で済ませる**【提案】（エンジンの直しが要らない）。
