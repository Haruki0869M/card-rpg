# 狭い画面（縦の低い画面）の配置の直し — 計画書

作った日: 2026-11-15（調査・設計役。**コードは変えていない。この文書だけ作った。コミットもしていない**）
基準の画面: **390×540**（LINE の中のブラウザを想定）。360×520 も見る。ふつうの画面 = 390×844・360×640。

---

## 0. 結論（先に）

1. **いちばん重いのは「世界マップの地図が狭い」でした。** 測ったら、390×540 では見えている地図が **73〜89px**（マス約2行ぶん）、災厄がいると **35〜51px**、360×520 では **0〜54px** です。しかも拡大のボタンの列（横206px×縦48px）がその上に乗るので、**駒がボタンの下に隠れて、マスがほとんど押せません。** LINE から来た相方は、世界マップでほぼ動けない状態です（憲章7「押せない所」に当たる）。前の見立て（「実機の数字をもらってから」）より、**先に直すのが良い**です。
2. **戦闘の状態の印は、狭い画面だけの話ではありませんでした。** 印は1つ 40×40px で、欄の幅に2つしか並ばず、3つ目からは「枠の中の見えないスクロール」に入ります。**390×844 でも、印が3つ以上ある敵は3つ目から見えていません**（白狼王に 脆弱・弱体・毒・❄隠れている を付けたら、毒と❄が見えなかった）。低い画面では、さらに見えている2つも下の端で切れます。
3. 直し方は「**低い画面の時だけ、形を切り替える**」です。ふつうの画面（390×844・360×640）の見た目は変えません（例外は 2. の「3つ目からの印」だけ。オーナーに聞く事 Q3）。
4. 作業は **3回**（世界マップの高さ → 世界マップの端 → 戦闘）。世界マップと戦闘はフォルダが別なので、作業者2人で並べて進められます。
5. **オーナーに聞く事は5つ**（最後の §8）。全部「おすすめ」で良ければ、「全部おすすめで OK」の一言で進められます。

## 2. 「低い画面」の決め方【提案】

- **決まり: 見えている高さ（`--app-h` と同じ値）が 640px より低い時 = 低い画面。** 22回目の `max-height: 639.98px`（`index.css:43`）と同じ線。
- ただし、CSS の `@media (max-height)` は「ブラウザが言う高さ」を見ます。LINE の中では、それが実際に見えている高さ（`visualViewport`）より大きい事があり（だから 22回目で `--app-h` を作った）、**CSS だけだと切り替わらない恐れ**があります。
- そこで、`useAppHeight`（`src/hooks/useAppHeight.ts`）が測った同じ値で、アプリのいちばん外（`[data-app-root]`。`App.tsx:268`）に **`data-low` の印**を付けます。部品は `useLowScreen()`（新しい小さな hook）か、CSS の `[data-low] …` で切り替えます。指で拡大中・文字入力中は測り直さない決まり（今のまま）なので、キーボードで形がばたつきません。
- 640〜699px（360×640 など）は**今回は変えません**（今の「次の目的の行を出さない」の 700px の線はそのまま）。360×640 の地図は 120〜174px と狭めなので、回1の出来を見てから「低い画面の形を 700px 未満まで広げるか」を後で相談します。
- 22回目のシートの `@media` は、今回は触りません（動いている物を変えない）。

## 3. 直し方（項目ごとに、おすすめ A と別の案 B）

### 項目3（先にやる）: 世界マップの地図の高さ

**目安【提案】: いちばん混んだ時でも、見えている地図が 390×540 で 200px 以上・360×520 で 180px 以上。ふつうの時（1人で野原を歩く）は 250px 以上。**（マス約6行。サイコロは最大6なので、行ける所がだいたい見える）

**A（おすすめ）: 低い画面の時だけ、上と下を細い形に切り替える。情報は消さず、置き場所を変える。**

| 部品 | 今 | 低い画面の形 | 浮く高さ |
|---|---|---|---|
| 上の帯の「次: 25%で…」 | 2〜3行 | 1行（入らない分は「…」。押すと今までどおり説明が開く） | 14〜29 |
| 災厄の札 | 4行 66px | 仲間の列の中の小さなボタン「💀×3」（44px。押すと今と同じ説明の窓）【提案・Q2】 | 66 |
| 「現在は P1（レオン）の手番です」の帯 | 29px | 出さない（すぐ下の「P1 レオンの番」と同じ事。ほかの人の番は「〇〇さんが操作しています」が出る） | 29 |
| サイコロの説明 | 2行 38px | 1行「移動力 1〜6（平均3.5）・★1で振り直し」 | 18 |
| 「サイコロを振る」＋野営・待機 | 2段 106px | 1段にまとめる（左に大きく「サイコロを振る」、右に小さく「野営」「待機」。どれも高さ44px以上） | 50 |

| 余白 | 上8・下12 | 上6・下8 | 6 |

- 計算: 390×540 で 上 52 ＋ 仲間の列 48 ＝ 100。パネルは、いちばん混んだ時（同行の行＋「〜に入る」）で約 240 → **地図 200px**。1人で野原なら約 138 → **地図 約300px**。360×520 は 180px／280px。
- 一緒に動く提案の窓（`MoveProposal`。`WorldScreen.tsx:146-`。約120px）も、低い画面では文を1行にして 80px ほどに。
- 拡大のボタンの横の列（206px）は、低い画面では「見取り図」と「🔍」の2つに畳む（🔍 を押すと ＋・標準・− が出る。ピンチでの拡大は今のまま）【提案】。右上をふさぐ幅が 206 → 約110px になる。
- カメラ: 駒を「見えている所」の真ん中に置く決まりは今のまま（`mapCamera.ts:20`）。見えている所が広がるので、駒はボタンの列の下から出る（列は上から 8〜56px、駒は約 80px より下）。

**B（別の案）: 操作パネルを「畳める」形にする**（取っ手を押すと1行の細い帯に畳まれ、地図が広がる。もう1度押すと開く）。地図はいちばん広くなるが、**ボタンを押すたびに開け閉めが要り**、「どこを押せば施設に入れるのか分からない」（前にパートナーから出た指摘）が戻る恐れ。A で 200px 取れるので、B は見送りをおすすめ。

### 項目1: 地図の端のマスが、固定のボタンの下に隠れる

**A（おすすめ）: 地図の右に「ボタンの列の分の余白」を足し、カメラがボタンの列を避ける。**
1. 地図の右に余白 72px（列の幅56＋右8＋すき間8）を足す（`WorldMap.tsx:788` の入れ物と、雲の海 `FogSea.tsx` の広がり）。右の端のマスを、ボタンの無い所まで引き出せる。
2. カメラの横の合わせ方に「右の、ボタンが隠している幅」を入れる（下のパネルの `inset` と同じ考え方を横にも。`mapCamera.ts` に `cameraLeft`・`revealLeft` の右の分）。手番が来た時・歩いた時・「手番のキャラへ戻る」を押した時に、駒が列の下に入らない。
3. 行き先を選んだ時: 選んだマスがボタンの下なら、自動で寄せる（`WorldMap.tsx:572-574`）。横の列（低い画面）の時は、上の 64px も同じ扱い。
4. 左・上・下は今のままで足りる（上と下は余白がある。左は地名の札だけで、押せなくならない）。確認で左の端も見る。

- 地名の札・♨ の札・駒は、どれも「動かせば出せる」ようになる。自動プレイの台本の「右・左・下・上に動かしてみる」（コミット 460c449）は残すが、**使われた回数が 0** を確かめる。

**B（別の案）: ボタンを小さく・1つに畳む**（「地図の道具」1つを押すと 見取り図・＋・標準・− が出る）。隠れる面積は減るが、**見取り図が1手遠くなり**（回1で「見取り図に気づかない」を直したばかり）、畳んだボタン1つの下のマスはやはり隠れる。A だけで足りるので、ふつうの画面では見送り（低い画面だけ、上の「🔍 に畳む」を使う）。

### 項目2: 戦闘の敵の状態の印

**A（おすすめ）: 低い画面の時だけ、印を「小さい札の1行」にして、HP のすぐ下（弱点の印と同じ行）に詰める。多い時は「＋2」。**
- 小さい札 = 高さ18px・絵と数字（字は12px）。弱点の印（▲🔥 ▼❄）の右に続けて1行。入らない分は「＋N」の札。
- **並べる順【提案】: 手を変える印を先に**（❄隠れている・🕯喰った灯・挑発・かばう → 脆弱・弱体・毒…）。
- 押した時: 小さい札は1つずつは押せない大きさなので、**その行を押すと「状態の一覧」**（その敵の印を全部、今の説明の文で）が開く【提案】。敵の長押しの説明にも、同じ一覧を足す（今は毒・脆弱などが長押しの説明に無い。`DetailPopup.tsx:120-135`）。長押しそのものは今のまま。
- 低い画面では、敵が1〜2体でも「短い形」（BREAK の条件は短い札・特殊な行動の案内は下の1行）を使う（今は3体以上だけ。`Battlefield.tsx:821` の `narrow`）。予告（大技・狙い・数字・5×2）は**そのまま**。
- これで白狼王の欄の下の端は 260 → **220px**（戦場の下の端 249／234px の中）。先読みの行（＋18）・案内の1行（＋20）が全部重なる珍しい時は、絵を 40 → 28px まで縮めて収める。
- 味方の欄も同じ小さい札にして、マナ・★の行の右に入れる（欄が伸びない → §1-3 の「25px はみ出す」も消える）。

**ふつうの画面（Q3）**: 40px の印はそのまま。**3つ以上ある時だけ、2つ目の場所を「＋N」の札にする**（押すと状態の一覧）。2つまでの時の見た目は今と同じ。

**B（別の案）: 印を敵の絵の上に重ねる**（絵の左上に縦に並べる）。縦は 0px で済むが、低い画面の絵は 40px しか無く、**絵がほとんど隠れる**。見送り。
**B'（別の案）: 味方の欄・手札を低くして戦場を広げる**。カードが小さくなり読みにくい。手札は遊びの芯なので見送り。

### 項目4: ♨ の札の字（小さな直し）

## 7. 相方のスマホの「画面の情報を見る」の写真が届いたら確かめる事

写真が無くても、390×540 を基準に3回とも進められます。届いたら次を見ます。

1. 「見えている高さ」と「使っている高さ」が 640 より低いか。→ 低ければ、この計画の形に切り替わる。
2. 「画面 ○×○」の縦（ブラウザが言う高さ）が 640 以上なのに、見えている高さが 640 より低い → §2 の心配が当たり（CSS だけでは切り替わらない）。`data-low` の印で切り替える作りが必要だった、と確かめられる。
3. 見えている高さが 500 より低い → 目安の 200px が取れない。その時は「同行の行を名前の行に入れる」などの追加を相談する。
4. 横幅が 360 より狭い → 1段にまとめたボタンの字が入るかを、その幅で測り直す。
5. 直した後の実機: 世界マップで右の端のマスが押せるか・戦闘で印が読めるか（オーナーと相方に見てもらう。台本では指の押しやすさは分からない）。

## 憲章の点検の後の直し（2026-11-15。記録: `docs/review/charter-audit-1115/small-screen-plan.md`）

結論は「方向は正しい・直してから」。**ここが上の節と食い違う所では、ここが勝つ。**

### 決まり（まとめ役が計画に足した物。【提案】はオーナーに伝える）
1. **低い画面で通しで遊ぶ確認を足す**: `adventure.mjs` を画面の大きさを選べる形にして 390×540 の2人を1本。オンライン2台の台本を 390×540 で1本（P2 の待ち中に 💀・🔍・状態の一覧が開けて閉じられる）。自動プレイは字でボタンを押しているので、**ボタンの字を変える時は台本も一緒に直す**（`data-` の印で押す形に寄せる）。
2. **切り替え**: `data-low` は「見えている高さ」で決める。入る線と出る線を分ける（640 未満で低い形に入り、672 以上で戻る）。描く前に値を決める（最初の1コマがふつうの形にならない）。入力中・拡大中は切り替えない。`data-low` の時は、CSS の高さの線（「次の目的」の行の 700px など）より `data-low` が勝つ。台本は `visualViewport.height` を偽った形でも確かめる。パソコンの低い窓でも低い形になる（オーナーに伝える）。
3. **災厄の札（低い画面）**: 世界マップでは「💀×N」のボタンに畳む（決定）。**町・神殿・祠の画面では畳まず、1行の短い帯で残す**【提案】（仲間の列が無く、店の値段などの悪さが見えなくなるため）。
4. **下のパネルの低い形に入れる物を全部決める**: 野営のボタンの夜襲%と💀回復半分・街道/湖の氷ボーナスの札・「同行を解除」・「助け起こす」・振った後の4つのボタン（360幅で字が入らない時は絵文字＋短い字。長押しか下の1行で全文）。**情報を消さない**（畳んだ物は必ず1回押せば読める）。
5. **寒さ・温泉の短い札は、押すと全文が出る**（「野営と温泉で防げる」が読めること）。
6. **拡大のボタン**: 低い画面はいつも畳んだ形（見取り図＋🔍）。🔍 を押すと ＋・標準・− が開き、もう1度押すか地図を押すと閉じる。
7. 地図の高さの目安（いちばん混んだ時 200px・360×520 は 180px）は、マスの説明の帯・扉の知らせ・一緒に動く提案の窓が出ていない時の数。出ている時の数も測って記録する（落とす線にはしない）。
8. **状態の印**: 並べる順（❄隠れている・🕯喰った灯・挑発・かばう を先に）は、どの画面でも直す。小さい札の行そのものは押す所にしない（下の予告と押し間違えるため）。**「＋N」の札だけを 44px の押せる大きさ**にして、押すと状態の一覧。敵の長押しの説明にも同じ一覧を足す。カードを選んだ時・スロットの板が出ている時・敵1〜2体の時も確かめる。
9. 4人・360幅の仲間の列（💀 を足すとはみ出す見込み）を台本で確かめ、はみ出すなら横に送れる形にする。
10. 低い画面の世界マップと戦闘の「前と後」の写真を、区切りごとにオーナーに見せる（main に入れる前に）。
