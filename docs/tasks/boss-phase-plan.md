### 1-3. 困っている所（ボス戦が山場になっていない理由）

1. **段階が「数字が上がるだけ」。** 28体のほとんどが「単体・全体・守り」の同じ3つの形で、段階で数が2〜3割上がるだけです。段階が変わっても、プレイヤーのやる事（弱点で殴る・大技を BREAK）は変わりません。新しいルールが入るのは、ガルド（呼ぶ）・月の乙女（再生）・回復する数体・夢喰い（フォーカス）くらいです。
2. **段階を見る前に終わる（推測。測って確かめる）。** 賢い bot の大物の戦闘は 3.7〜4.6 ラウンド（回復役入りの2人は 6.6〜7.4）。境目が50%なら、後半は1〜2ターン、最後のボスの30%の段階は0〜1手で終わっていそうです。一撃で境目を2つ越えると、途中の段階は1回も出ません。
3. **変わり目に読み合いが無い。** 前もっての知らせが無く、変わっても今の予告はそのまま。「ここで半分を切ると、次に何が来るか」を考える材料がありません。
4. **ボス戦で負けが出ない。** 賢い bot・工夫する bot の負けは、今は全部「侵食度100%（時間切れ）」で、全滅は0回です（`2026-11-13-time-pressure.md`）。ボスが「怖い相手」になっていません。
5. **夢の迷宮の鍵のボス3体は、ほかの最後のボスの写し**です（物語では「夢のこだま」）。憲章5の「コピペ」に近い所です。

## 2. 案【提案】

### 柱1: 変わり目を「読める山場」にする（全部のボスに共通の決まり。エンジン）

- **HPバーに境目の線を引く。** ボスのHPバーに、段階の境目の所へ細い線（▼）。長押しで「HP50%を切ると『怒れる炎竜』になる。最初に〇〇をしてくる」。
- **境目を切った時、今の予告は変えない**（理不尽な割り込みにしない）。代わりに、**次の予告は必ず、その段階の「開幕の一手」**（段階ごとにデータで1つ決める。新しい口 `EnemyPhaseDef.openingActionId`）。予告の枠に「🌀第2段階」の札。
  - 開幕の一手は、その段階の新しいルールを見せる行動（呼ぶ・溜める・弱点が変わる、など。柱2）。大技なら、今のBREAKの決まりで止められる。
  - これで「今このターンに半分を切るか、守りを整えてから切るか」という悩みが生まれます。一気に倒し切る火力のビルドは、開幕の一手を見ずに勝てる（ご褒美）。
- **一撃で2つ越えた時も、開幕の一手は1つだけ**（深い方の段階の物）。途中の段階は飛ばしたまま（火力のご褒美を消さない）。
- 「溜め」の行動は、今ある先読みの入れ物（`queuedActionId`）を使い、予告の下に「次: 〇〇」を出す（オカメインコの先読みと同じ見え方）。

### 柱2: 段階で「ルール」が変わる（ボスごとにちがう形。コピペ禁止）

段階ごとに、**新しいルールを1つだけ**足します（数を上げるだけの段階は作らない）。同じシナリオの4体は、全部ちがうルールにします。使う部品は、なるべく今あるもの。

| 紫の札を解く | 手数読み・癒し封じ・手負い狙い・盾砕き・浄化 | 今ある |

### 柱3: 回復役がいなくても戦える道を残す

- 上の表のとおり、どのルールにも「回復しないで済む答え」（BREAK・先に倒す・守り・一気に削る・合う属性）を1つは用意します。
- 開幕の一手は、境目を切った**次の**予告に出るので、必ず1ターンの準備があります。
- 消耗品（閃光の破砕玉など）で止められる事は、今の決まりのまま。

### 柱4: 数字は最後に、測ってから

- まず仕組みだけで測ります。足りない時に、境目の%（例: 50% → 60%）か、開幕の一手の威力を小さく動かします。ボスのHP・攻撃の倍率（案Y の形）は使いません。カードは弱くしません。

## 3. 画面・2人で遊ぶ時・保存

- **画面（360×640）**: HPバーの線は細い縦線1本と小さな ▼（文字は出さない）。段階の札「🌀2」は、強敵の本気の橙の札と同じ所・同じ大きさで、色だけ変える（青紫）。狭い時は短い文字（「🌀2段」）。変わった時の知らせは今のポップアップ・音のまま、ログに「次は〇〇をしてくる」を足す。数え読みは予告の枠の右上に小さな数字。Playwright で 360×640 の画像を撮って、ほかの札と重ならないかを確かめます。
- **2人で遊ぶ時**: 新しいボタン・操作は足しません（見せる物だけ）。だれかが止まる所は作りません。段階・開幕の一手・数え読み・弱点の上書きは、戦闘の状態（敵の `phase` と数1つ）に入るので、オンラインの同期でそのまま両方の画面に届きます。
- **乱数**: 新しいルールは乱数を使いません（ターンの数と段階の番号で決める）。仲間を呼ぶのは今の部品のまま（種から作る `Rng` だけ）。
- **保存と再開**: 足す状態は省いてよい形にします（無い時は「まだ開幕の一手を出していない」と同じ）。ボスの行動の一覧が変わるので、古い保存の戦闘の途中で順番の位置がはみ出さないこと、開幕の一手を2回出さないことをテストで確かめます。弱点は保存せず、段階の番号から毎回求めます（保存と画面がずれない）。

## 4. 測り方

- 道具: `src/engine/__tests__/twoBots.sim.test.ts`（重い確認は `C:/dev/card-rpg-tools/heavy.mjs` を通す）。シナリオ1・ふつう・回復役入りの既定の組（2人 剣士＋僧侶 / 3人 剣士＋魔法使い＋僧侶 / 4人 剣士＋魔法使い＋狩人＋僧侶）。賢い bot が主。直行 bot・工夫する bot も流す（直行は中盤で全滅、を確かめる）。40種。
- 足す数え（テストの側だけ）: ボス戦のラウンド・**段階ごとのラウンド**・2段目／3段目まで行った割合・開幕の一手が出た回数とその BREAK・ボス戦で倒れていた味方・**ボス戦での全滅**・ボス戦に入った時のHPの割合。
- 前と後の表: クリア率・負け方（全滅 / 侵食度100%）・負けた場所・上の数え。2人の組（回復役なし: 剣士＋狩人・魔道士＋召喚士）も20種で、「回復役なしでも0%にならない」を見ます。
- シナリオ1で形を決めたら、ほかの6本は軽い確認（短い測定）だけにします（今の決まり: 運用の確認はシナリオ1）。
- 目標の見方: 賢い bot（回復役入り）のクリア率は、この段だけで15〜40%まで下げようとはしません（キと時間で残りを作る）。この段で見たいのは、**負けの一部が「ボス戦の全滅」に移る事**と、**段階ごとのラウンドが1以上になる事**です。
