## 項目1: 世界マップの下のパネル・初めのカメラ・移動の演出

### 今の作り（調べた結果）
- 画面は上から「上の帯 → 仲間の列 → 地図（`flex-1`）→ 移動の提案 → マスの説明（`info`）→ 手番の帯 → 操作パネル」の縦並び（`WorldScreen.tsx` 336〜535行目）。下のパネルの高さが増えると、その分だけ地図が狭くなる。
- 行き先を選ぶと、マスの説明の行（349行目）と「移動する（移動力 N）」のボタン（495行目）が増え、パネルが高くなる。
- 移動中は、パネルの大きさを**変えないまま**、上に「移動中… 0/2 マス」の帯（`WorldMoveScene.tsx` の `MoveStatus`、`absolute inset-0`）を重ねている。地図の大きさが変わらないようにした作り。だからパネルが大きいままになり、駒が地図の下の端に隠れる。
- カメラは「手番の駒を地図の真ん中へ」（`WorldMap.tsx` 188〜193行目）。ただし、合わせ直すきっかけは駒・手番・**地図の幅**だけで、**地図の高さが変わった時は合わせ直さない**。また地図の端の近くでは、スクロールがそれ以上動けず、駒が真ん中に来ない。
- 地図のマスの大きさ（`useMapGeom`）は**幅だけ**で決まる。高さが変わっても、マスの大きさや駒の位置はずれない（＝下のパネルを小さくしても、駒が作り直される心配はない）。
- 移動力の判定の結果（`RollStrip`、`CheckPanel.tsx` 111〜137行目）は、1つずつ 0.05 秒おきに出るだけで、回る間が無い。
- 歩く時間 `TIMING.worldMoveStep 0.17`・到着 `worldArrival 0.3`（`balance.ts` 189〜190行目）。記録では「到着 → 暗転 →『！』→ 窓」まで約1.2秒。

### 直し方
1. **初めのカメラ**（`WorldMap.tsx` 186〜193行目・235〜236行目）
   - 地図の中身の上下左右に「見えている枠の半分」の余白（霧と同じ暗い色）を足し、端のマスでも駒を真ん中に置けるようにする。
   - 合わせ直すきっかけに**地図の高さ**（`size.height`）を足す（パネルの高さが変わった時も駒が見える）。
   - 最初に、記録の写真と同じ状態（始めの町・2人）で原因を測って確かめる（「端で止まる」か「高さの変化で合わせ直していない」か、両方か）。
2. **行き先を選んだ時**（`WorldScreen.tsx` 349・411〜415・486〜498行目）
   - マスの説明（`info`）を、パネルの外の別の行ではなく、パネルの中の「光るマスをタップして…」の案内の行と**入れ替える**（行が増えない）。
   - カメラは「今の駒と選んだマスの中間」に合わせる（行き先と駒が両方見える）。【提案】
3. **移動中は小さな帯にする**（`WorldScreen.tsx` 351〜356行目・`WorldMoveScene.tsx` 64〜78行目）
   - 移動の演出の間は、手番の帯と操作パネルを**出さず**、高さ約72pxの帯（`MoveStatus`）だけにする。地図がその分広がり、カメラは歩いている駒に付いていく（今の 188行目のしくみ）。
   - 到着して次の画面に移るか、手番の画面に戻った時に、パネルを元に戻す。戻った瞬間にもカメラを合わせ直す（上の 1 の「高さ」）。
   - 今の「地図の大きさを変えない」約束は、マスの大きさが幅だけで決まるので守られる（駒の作り直し0回・ずれ0px を `world-move-stability.mjs` で確かめる）。
4. **歩数の表示**（`WorldMoveScene.tsx` 76行目・`WorldScreen.tsx` 495行目）
   - 移動中:「移動中…（残り2歩）」→「移動中…（残り1歩）」→「到着しました」。【提案】数え方は「1マス = 1歩」。
   - 選んだ時のボタン:「移動する（移動力3を使う・2マス先）」。マスに出る数字（使う移動力）と歩数の違いを、ここで一度だけ言葉にする。【提案】
5. **移動力の判定のスロット**（`CheckPanel.tsx` の `RollStrip`・`WorldScreen.tsx` 412行目）
   - `RollStrip` に「回す」の指定（`spin`）を足す。押した直後だけ、各枠が約0.35秒くるくる回って（○×が入れ替わる見た目）から、左から順に止まる。結果は押した時にもう決まっているので、**乱数・状態には触らない**。
   - 使うのは世界マップの移動力の判定と、ダンジョンの探索力の判定（`DungeonScreen.tsx` 586行目の近くの `RollStrip`。オーナーが決めた）。ほかの判定は今のまま。
   - 「動きを減らす」の設定・高速モードの時は回さない（今の演出と同じ扱い）。
6. **到着の後の待ちを詰める**（`balance.ts` 190行目・イベントの窓の出方）
   - まず、到着〜窓までの約1.2秒の内訳を確認スクリプトで測る（到着 0.3秒 ＋ 画面の切り替え・「！」・窓の出る演出）。
   - 目標は**合わせて約0.7秒**。【提案】`worldArrival` を 0.3 → 0.25 に、イベントの窓の出る演出の待ちを短くする（どこを削るかは測ってから決める）。歩く速さ（0.17秒/マス）は変えない。
   - `balance.ts` の `TIMING` はフェーズ1も触っているので、フェーズ1が入った後に直す。

### 自分で決める所（提案）
- 移動中の帯の高さ 72px、行き先を選んだ時のカメラの位置（中間）、文言「残り○歩」「移動力3を使う・2マス先」、スロットの回る時間 0.35秒、到着〜窓の目標 0.7秒。

### 保存・同期・乱数・actorOf
- 保存: 変えない。 同期: 変えない（演出は各端末の見た目だけ）。 乱数: 使わない（スロットの見た目は結果を後から見せるだけ）。 actorOf: 新しい操作は足さない。

### テストと確認
- テスト: カメラの位置を決める関数（余白込みの中央・中間）と、帯の文言（残り○歩）を純粋な関数に分けて、vitest で確かめる。
- 確認スクリプト: `world-move-stability.mjs`（駒の作り直し0回・止まっている駒のずれ・霧と敵の先出し0回）に「移動中の下の帯の高さが 90px 以下」「歩いている駒が地図の見える範囲に入っている」「始めの画面で駒が地図の縦の真ん中から±20%以内」を足す。`check-layout.mjs`・`movement-pet-colors.mjs`・`companion-move-agree.mjs`・`adventure.mjs`（2人/4人）も通す。

## 項目2: 1台で遊ぶ時の同行の確認を省く・手番の表示を1つにまとめる

### 今の作り

- 「誘う」は、1台で遊ぶ時はその場で自動で承知にしている（303〜305行目）。移動の提案は自動にしていない。

### 直し方
1. **同行の確認を省く**（`WorldScreen.tsx` 316〜330行目 `tapTile`）
   - 1台で遊ぶ時（`!isOnlinePlay()`）は、`WORLD_MOVE` を送った直後に、提案ができていたら、その提案の担当の人（全員この端末の人）の「一緒に行く」（`WORLD_MOVE_AGREE` accept、heroId はその担当の同行キャラ）を続けて送る。「誘う」の自動の承知と同じやり方。
   - 確認の窓（`MoveProposal`）は、1台で遊ぶ時は出さない（一瞬出て消えるのも防ぐ）。
   - **オンライン**（別の端末の人を連れて動く時）は今のまま、同意を取る。
   - 1台で同行をやめたい時は、今の「同行」の顔のボタン（424〜451行目）か「同行を解除して単独行動する」（417行目）で、動く前に外せる。
2. **手番の表示を1つにする**（`WorldScreen.tsx`・`TurnCutin.tsx`）【提案】

   - その画面を、カットインと同じ見た目（プレイヤーの色の帯が滑り込む・顔・「P2 セシルの番！」）にして、帯の下に「スマホを P2 さんに渡して、タップで始める」を出す。

### 自分で決める所（提案）

## 項目3: 町（所持金・購入の手応え・下の余白・タブ・転職の条件）

2b. **すぐ装備する**（オーナーが決めた: お知らせと両方入れる）

## 項目4: ダンジョン（地図と案内の重なり・最初の判定の案内）

### 今の作り
- 「扉は全員が『開ける』を選ぶと開きます」の文（`DungeonScreen.tsx` 323〜329行目）は、2人以上なら、1台で遊ぶ時もいつも出ている（z-10）。全体の地図（`MapOverlay`、z-30、背景 95% の不透明）を開くと、地図の左上の見出し「地図（探索度 24%）」の裏に透けて重なる。
- 入った直後や手番の始めで「探索力の判定」をまだしていない時（`run.explore == null`）、移動のボタンは全部暗いだけで、理由が出ない（331〜347行目、`ExplorePanel` 548〜579行目）。
