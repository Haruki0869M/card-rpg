## 項目1: お供を迎える画面（シルエット → ポン！の演出）

### 今の作り
- 画面は `HeroTasks.tsx` の `AdoptPet`（34〜95行目）。外枠（`Frame`、24行目）の背景は 97% の不透明で、少し後ろが透ける。
- お供の絵は `PetToken` の大きさ 84px（59行目）。珍しい色の時だけ 0.7秒光る（`index.css` 466〜468行目 `pet-rare-reveal`）。
- 毛色は開いた時にもう出ている（「黄緑 出会った時の毛色です」、70〜74行目）。毛色はエンジンが先に決めて `hero.petOfferColors` に入れている（`outcomes/kinds/pet.ts` 19行目）。
- 伝承の書（`profile.ts`）は、お供を「種類:色」で、出会った（seen）と迎えた（got）を記録している（56〜57行目・241〜250行目）。

### 直し方
1. **背景を不透明に**: `Frame` の背景を 97% → 100%（`bg-[#0b0910]`）。ほかの画面（カードの強化・行商人）も同じ外枠なので、一緒に不透明になる（問題なし）。
2. **絵を大きく真ん中に**: `PetToken` を 84px → **152px**（約1.8倍）。説明・能力の文は下へ。360px の画面で「名前」の入力欄と「お供にする」のボタンが画面に収まるよう、説明の文を2行までに縮める（長い時は「くわしく」で開く）。【提案】
3. **シルエット → ポン！の演出**（新しい小さな部品 `PetReveal`。見た目だけ）
   - 0〜0.6秒: お供の形の黒いシルエット（絵に `brightness(0)` をかけた物）が、ふわふわ上下に揺れ、まわりに小さな光の粒が集まる。毛色の欄は「？？？」。
   - 0.6秒: 「ポン！」と白く光って、毛色の付いた姿が少し大きく（1.15倍）弾んで出る。ここでお供の鳴き声（今の `petCry`、小さめの音量）を1回鳴らす。
   - その後: 毛色の欄に「毛色：黄緑（通常の色）」または「毛色：白（✨珍しい毛色！）」。珍しい色の時は今の金色の光（`pet-rare-reveal`）を続けて出す。
   - **初めて迎える組み合わせ**（伝承の書の `pets.got` に「種類:色」が無い）なら、絵の右上に「NEW!」の札。判定は画面を開いた時の記録で決める（開いた瞬間に「出会った」が記録されても、NEW は消えない）。
   - 候補が2匹以上の時（上の選ぶボタン）は、別の子を選ぶたびに短い版（0.3秒）で出し直す。【提案】
   - 画面をタップすると演出を飛ばしてすぐ出す。「動きを減らす」の設定・高速モードの時は、シルエットを0.2秒にして光を出さない。
   - 「名前」「お供にする」は、ポンの後に押せるようにする（演出の間に押し間違えない）。
4. **音**: 鳴き声は「静かでやわらかい音」の方針（メモリ: quiet-soft-sounds）に合わせて、音量を小さめに。新しい音は作らない（今の鳴き声を使う）。

### 保存・同期・乱数・actorOf
- 保存: 変えない（伝承の書は読むだけ）。 同期: 変えない（毛色はエンジンが決めた物を見せるだけ）。 乱数: 使わない。 actorOf: 新しい操作は無い（今の `ADOPT_PET`）。

### テストと確認

## 項目2: カードの報酬（基本のカードを出さない・同じ名前を重ねない・押してから決める）

### 今の作り
- 報酬は、生き残ったキャラ1人ずつに3枚（`game.ts` 776行目 → `loot.ts` 92〜112行目 `rollCardOffers`）。1枚目はジョブ・系統・武器種のカード（`heroJobCardPool`）、2枚目まではスマート抽選、3枚目は完全ランダム。
- 同じキャラの中では、**同じ ID** だけ重ねない（110行目）。ID が違って名前が同じカードは重なる。最初の山札のカード（ガードなど）も候補に入る（僧侶・守護者の候補の表にガードがあるため）。
- 最初の山札のカードの一覧は、もう `cardTags.ts` 52〜53行目に `starterIds()`（どこかのジョブの最初の山札に入っているカード）がある。今は「好みの判断に使わない」ためだけに使っている。
- 報酬の画面（`RewardScreen.tsx` 57〜160行目）は、めくった後にカードを1回押すと、すぐ `PICK_CARD` を送る（122行目）。カードには説明文が無い（数字と記号だけ）。
- 町のカード売り場（`Places.tsx` 286〜312行目）は、カードの下の値段のボタンを1回押すとすぐ買う。

### 直し方（エンジン: `loot.ts` の `rollCardOffers`）
1. **基本のカードを出さない**: 候補から `starterIds()`（`cardTags.ts` から export する）に入るカードを外す。【提案・オーナーに確認】外す範囲は下の「決めてほしいこと 1」。
   - 外した後に候補が空になる時（とても狭いジョブ）は、今までどおりの候補に戻す（報酬が出ない、を防ぐ）。
2. **同じ名前を重ねない**: 同じキャラの3枚の中で、**カードの名前**が同じ物を重ねない（今の「同じ ID」に加えて）。
3. 1枚目は今のまま「ジョブ・系統・武器種のカード」。2枚目のスマート抽選・3枚目の完全ランダムも今のまま。
4. 試す回数（今 30回）で3枚に届かない時は、今と同じく、出せた枚数だけ出す。

### 直し方（画面: 押してから決める）
5. **新しい部品 `CardPickPanel`**（`src/components/ui/CardPickPanel.tsx`、新しいファイル）
   - カードを押すと、そのカードが少し大きくなり（今の 1.15倍・前に出る）、下に**説明の窓**が出る:
     - 1行目: ひとことの説明（例:「敵全体に物理ダメージ」「味方1人のHPを回復」）。カードの対象（`card.target`）と種類（物理・魔法・技）、主な効果から作る。【提案】作る関数は `src/components/format.ts` に足す。
     - 2行目から: 成功の数ごとの効果（今の図鑑の `DataCatalog.tsx` 128行目と同じ `describeEffect` を使う）と、このキャラの成功率。
     - ボタン:「このカードを選ぶ」（報酬）／「〇〇Gで買う」（店）。窓の外を押すと閉じる。別のカードを押すと、そちらに切り替わる。
   - 今の「めくる」演出（裏返し・レアの光）は今のまま。めくり終わってから押せる。
6. **報酬の画面**（`RewardScreen.tsx` 116〜125行目）: カードを押すと上の窓を開く。`PICK_CARD` は「このカードを選ぶ」でだけ送る。「スキップ」（312行目）は今のまま。
7. **店**（`Places.tsx` 291〜310行目）: カードを押しても、値段のボタンを押しても、上の窓を開く。買うのは窓の「〇〇Gで買う」でだけ。【提案】値段のボタンを押してもすぐ買わない（押し間違えを防ぐ）。
8. 窓の文字は12px以上。360px で、カード3枚＋窓が画面に収まること（窓は下からせり上がる形）。

### 自分で決める所（提案）
- ひとことの説明の作り方（対象＋種類＋主な効果）、窓の形（下からせり上がる）、店で値段のボタンも窓を開く所。

### 保存・同期・乱数・actorOf
- 保存: 変えない。報酬の途中の保存は、もう決まった3枚がそのまま出る。
- 乱数: **報酬のカードの抽選の結果が変わる**（候補が減り、名前の重なりを避けて引き直すため、乱数を使う回数が変わる）。その後の乱数の流れも変わるので、自動プレイの結果が今と別の流れになる（`CLAUDE.md` §7「乱数の順番が変わると古い不具合が出る」に注意。新しい不具合か古い不具合かを見分ける）。
- 同期: エンジンは純粋な関数のままなので、オンラインでも全員同じ結果（同じ版どうし）。
- actorOf: 新しい操作は無い（`PICK_CARD`・`TOWN_BUY` のまま）。
- **難しさへの影響**: 報酬から弱い基本のカードが減るので、少し強くなる方向。数値は下げないが、念のため自動プレイ（侵食の魔王・ふつう・40シード・2人/4人）で、クリア率が目安（2人約85%・4人約90%、±10）から外れないか確かめる。外れたら報告して、オーナーに相談する（勝手に敵を強くしない）。

### テストと確認
- テスト（vitest）: 多くの種（例: 200種）で `rollCardOffers` を回して、①基本のカードが出ない ②同じキャラの3枚に同じ名前が無い ③1枚目がジョブ・系統・武器種のカード（今の K7 のテストを残す）④3枚出る（候補が狭いジョブも）。
- テスト: ひとことの説明の関数（全体攻撃・単体攻撃・回復・ブロック・支援の例）。
- 確認スクリプト: `playthrough.mjs`・`adventure.mjs`（報酬の画面で、押す → 窓 → 選ぶ、の流れに直す）、`chest-show.mjs`。報酬・店の窓を 360/390/480 で撮る。`check-layout.mjs`・`interaction-safety.mjs`（押し間違いの確認）。
