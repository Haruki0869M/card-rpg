# ホストの引き継ぎの直し（憲章7 の宿題）— 計画

点検: `docs/review/charter-audit-1113b/B.md` 3-4・`docs/review/2026-11-13-charter-audit2.md`・`docs/review/charter-audit-1113/D.md` 2-2。

## 1. 待ちを短くする（今 約95秒）

今の流れ: 眠る → 最後の「動いている」から35秒で止まったとみなす（実際は 25〜35秒 ＋ 見回り5秒以内）→ 相方がホストを引き継ぐ → **そこから60秒**数えて「代わりに操作する」が出る。合計 約90〜100秒。

直し: 「代わりに操作する」が出る時刻を、**気づいた時から60秒**ではなく、**その人が最後に「動いている」を書いてから35秒（= 止まったとみなす時）**にそろえる。
- 止まったとみなした時には、もう35秒動きが無いので、ほぼすぐに出る（気づいてから最低5秒は待つ。戻ってくる瞬間にボタンが出たり消えたりしないため）。
- 通信が切れた（online が false）人は、最後の「動いている」から35秒たつまで待つ（今までの「60秒」より短い）。
- 「もう少し待つ」を押したら、30秒あとにまた出す。
- 結果: 眠ってから 約30〜45秒で「代わりに操作する」が押せる。

【提案】気づいてから最低 5秒・「もう少し待つ」は 30秒（前は60秒やり直し）。止まったとみなす 35秒（STALE_MS）は変えない（短くすると、別のアプリを少し見ただけでホストが替わりやすくなるため）。

## 2. 古いホストが目を覚ました瞬間の上書きを防ぐ

今: ホストは依頼を処理すると `log/番号` を、だれかがもう書いていないか見ずに書く。目を覚ました古いホストが、たまっていた依頼を1つ処理すると、新しいホストが書いた番号を別の操作で上書きしうる。

直し（`database.rules.json` は変えない。Firebase の transaction を使う）:
1. 記録は「その番号がまだ空の時だけ書く」（`log/番号` への transaction）。書けなかったら、だれかが先に書いた = 自分は遅れている → 部屋の記録に追いついてから、その依頼をやり直す（新しいホストに替わっていたら、処理をやめる）。
2. 依頼の処理を始める前に、部屋の `hostUid`・記録・依頼の一覧を読み直す（今の「記録に追いつく」読みと一緒に、同時に読むので待ちは増えない）。自分がもうホストでなければ処理しない。部屋にもう無い依頼（新しいホストが処理済み）は捨てる。記録の古い分が消えていて追いつけない時は、保存から取り直す。
3. 記録に「どの依頼から作ったか」（依頼のキー）を入れ、処理済みの依頼を二重に記録しない。
4. 断る（エラーを返す）前に、次の番号の記録がもう無いかを確かめる（古い状態で断って、相方の操作を消さないため）。
5. 状態の保存（snapshot）も「今の保存より新しい時だけ書く」（transaction）。

ホストの画面の速さ: 自分の操作をすぐ画面に出すのは今のまま（書けなかった時だけ、取り直して直す）。

## 3. 扉の投票の待ちにも「代わりに操作」の窓を出す

`awaitedSeats`（待っている席）に、「ダンジョンの中の、みんなで決める場面（扉・撤退・イベントの選択・続ける・宝箱の開け役など）で、まだ選んでいない席」を足す。戦闘中は今のまま。
- 代わりに操作を始めたホストが扉を押すと、自分と代わりの席の両方の票が入る（今の作りのまま）。
