# 操作・演出の改善（J4の前に実施）

オーナーは2026-11-08に6項目の計画を承認。前半を実装・検証・報告し、その結果を確認してもらって後半へ進む。J4とHosting再公開はこの作業に含めない。

## 前半（実装済み）

1. 世界マップの経路を1マスずつ駒/お供が進む→到着演出→遭遇/イベント/施設操作。敵マスでも地図を消さず最後まで再生し、戦闘開始はプレイヤーの操作を維持する。
2. お供の毛色を候補生成時のRngで決めて保存。通常2色各35%、珍しい2色各15%。全12種4色に統一し、名前入力は残す。珍しい毛色の表示/短い光/採用ログ。旧保存v11→v12は未選択候補だけ補完、既存のお供は維持。

- 表示待ちはstore.worldMovesの端末内キュー。確定状態/同期/保存は待たせず、受信結果を巻き戻さない。同じ場面の追加操作は表示後。再接続では過去の移動を再生しない。
- 通常1マス0.17秒/到着0.3秒、高速は半分。TIMINGから調整。動作軽減でも経路と画面順は維持。
- adventure.mjsはdata-world-movingが消えるまで待つ共通関数を使用。待機上限15秒、演出中は停滞回数を増やさない。
- 検証: petColors.test.ts・worldMovement.test.ts・room.test.ts、scripts/movement-pet-colors.mjs（3幅、通常/高速、4種類の到着、毛色保存再開、OS動作軽減）。最終結果と冒険の種はSTATUS参照。
- 保存されたお供候補の画面がタイトルを覆う既存問題も、冒険再開後だけ表示する修正で対応。

## 後半（オーナーのOK後に実装済み）

3. お供アイコン/名前/効果名の0.6〜0.8秒カットインとトークンの跳ね。探索は適用された操作で通知し、描画で繰り返さない。
4. 行動者の踏み込み→対象の被弾と数値。ブロック/回復/状態名の区別。演出の上書き・4人時の文字重なりを防ぐ。
5. 現職/引き継ぎ/お供/装備の出所を持つ汎用の発動通知。ジョブIDや能力名で分岐せず、実際に適用された時に表示、二重通知を防ぐ。
6. 端末ごとの速度「通常/高速」と能力カットイン「標準/簡易」、既存の振動を維持。旧設定の補完とOS動作軽減。

難易度・戦闘数値・武器・公開設定は変えない。各区切りで型チェック・全テスト・ビルド・画面確認・日本語報告・コミット・bundle。pushしない。

## 後半の実装と確認

- 発動の出所をAbilitySourceで持たせ、AbilityNotice/BattleEventへ渡す。既存の効果や乱数の順序は変えず、現職/継承/装備/お供/召喚を区別する。開始時の捨てられていた演出イベントをopeningEventsに保持し、新しい戦闘に入った時だけ表示。
- store/presentation.tsは戦闘の動き→効果と探索の通知を純粋に組み立て、battleStoreが端末内タイマーで再生。3段の固定ポップアップ、お供2件ずつの0.7秒表示と跳躍。長い連撃の後半を合算。ゲーム結果・保存・同期は待たせず、結果画面だけ最後の効果表示後に開く。
- SettingsControlsをタイトル/メニューで共用。通常/高速・標準/簡易・振動、旧設定の補完、OS動作軽減。保存v12→v13は出所の補完のみ、旧効果と乱数を維持。
- テストは後半で29件追加。全453件成功・3件スキップ。型チェック・ビルド成功。既存2件は追加メタデータを含む厳密な期待値へ更新し、版番号の期待値は13へ更新。既存テストの削除なし。
- scripts/battle-feedback.mjsで3幅の設定保存/4人のお供/屍兵/砲台/罠/攻撃/継承/歌/簡易高速の追撃と動作軽減を確認。短い高速通知は表示履歴でも確認する。
- adventure/playthroughはwaitForBattlePresentationを使い、戦闘終了の表示待ち中に次の操作を誤送信しない。待機上限15秒で停止を検出。冒険4ケースと既存戦闘、前半の移動/毛色の再確認結果はSTATUS参照。
