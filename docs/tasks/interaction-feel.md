# 操作・演出の改善（J4の前に実施）

オーナーは2026-11-08に6項目の計画を承認。前半を実装・検証・報告し、その結果を確認してもらって後半へ進む。J4とHosting再公開はこの作業に含めない。

## 前半（実装済み）

1. 世界マップの経路を1マスずつ駒/お供が進む→到着演出→遭遇/イベント/施設操作。敵マスでも地図を消さず最後まで再生し、戦闘開始はプレイヤーの操作を維持する。
2. お供の毛色を候補生成時のRngで決めて保存。通常2色各35%、珍しい2色各15%。全12種4色に統一し、名前入力は残す。珍しい毛色の表示/短い光/採用ログ。旧保存v11→v12は未選択候補だけ補完、既存のお供は維持。

- 表示待ちはstore.worldMovesの端末内キュー。確定状態/同期/保存は待たせず、受信結果を巻き戻さない。同じ場面の追加操作は表示後。再接続では過去の移動を再生しない。
- 通常1マス0.17秒/到着0.3秒、高速は半分。TIMINGから調整。動作軽減でも経路と画面順は維持。
- adventure.mjsはdata-world-movingが消えるまで待つ共通関数を使用。待機上限15秒、演出中は停滞回数を増やさない。
- 検証: petColors.test.ts・worldMovement.test.ts・room.test.ts、scripts/movement-pet-colors.mjs（3幅、通常/高速、4種類の到着、毛色保存再開、OS動作軽減）。最終結果と冒険の種はSTATUS参照。
- 保存されたお供候補の画面がタイトルを覆う既存問題も、冒険再開後だけ表示する修正で対応。
