## 1. 結論（先に）

- **今のダンジョンの「部屋のつながり」（部屋の種類・並び・投票・場面・戦闘/宝箱/イベント/休憩）はそのまま使い、その上に「歩ける通路の地図」をかぶせる**作り方を提案します。
  - 部屋の中で起きること（戦闘・宝箱・イベント・休憩・ボス・大宝箱・撤退）は今の処理をそのまま使うので、壊れる所が少なく、オンラインの同期もそのまま使えます。
  - 新しく作るのは「通路の地図を作る」「歩く・向きを変える」「見た所を地図に描き足す」「一人称の絵」「ミニマップ」です。
- **3つの段階**に分けます。各段階の終わりに、テスト・型チェック・ビルド・画面の自動確認を全部通し、コミットして報告します（push・公開はしません）。
  - **段階A**: 歩く仕組み・保存・bot・テスト（画面は大きな地図＋前進/左/右のボタンの仮の見た目。これだけで遊べる）
  - **段階B**: 一人称の通路の絵・奥へ進むズーム・扉が開く演出・右上のミニマップ・探索度・下のパネルの並べ替え
  - **段階C**: 感知・フクロウなどで「1つ先の扉の気配」、絵（Midjourney）と音の差し込み口、実機の確認

### 2.2 仕組み（エンジン）
- **作る**: `engine/game/dungeon.ts` の `buildDungeon`。敵・宝箱の見た目・イベントは入った時に `Rng` で決まる。ランダムダンジョンは `randomDungeonSeed` から作る（同じ種なら同じ形）。
- **進む**: 1行目から上へ。今の部屋を終えたら、`next` の部屋（1〜3つ）から1つを選ぶ（`reachableRooms`）。**選ばなかった部屋には戻れない**（一方通行）。
- **部屋に入る**: `ENTER_ROOM` → `rooms/behaviors/*.ts` の動きで、戦闘・宝箱・イベント・休憩の画面になる。終わると `mode = 'dungeon'` に戻る。
- **探索力（M3-D）**: 世界マップがあるシナリオでは、ダンジョンの組も世界マップの手番の順番で動く。番の最初に `EXPLORE_ROLL`（素早さ×2枠、フォーカスで確定成功。`探索力 = 2 + 成功数` で 2〜4）。**部屋に1つ入るごとに1減る**。0になって通路に戻るか、`EXPLORE_END`（手番を終える）で次の人の番（`game.ts` の SCENE の処理の最後）。
- **場面**: ダンジョンに入ったキャラは `game.expeditions` に分かれ、操作は `SCENE` で包む（`scenes.ts`）。
- **みんなで決める**（`votes.ts`）: ダンジョンの中の `ENTER_ROOM`（**全員一致**）・`RETREAT`・イベント・休憩・宝箱を去る・帰還・手番を終える は、場面に2人以上いれば投票。票は「今の場面の目印」（`voteCtx`: mode・今の部屋・イベント…）が変わると無効になる。
- **撤退**: `RETREAT`。手に入れた宝のうち1つを失う。
- **見える化**: spec §2・§9.1 で「**部屋の中身は入る前からアイコンで見える**」と決めている。今の画面は全部の部屋の種類・敵・宝箱の確率が最初から見える。

### 2.3 画面
- `components/screens/DungeonScreen.tsx`（456行）: 縦スクロールの部屋の地図（丸いアイコンと線）、部屋をタップ → 情報と「この部屋へ進む」、投票の席の色の印、探索力のパネル（`ExplorePanel`）、下にパーティの顔と HP・装備・道具・撤退。

## 3. 作り直しの設計案

### 3.1 通路の地図（区画の地図）
- 今の「部屋のつながり」から、**マス目の地図を自動で作る**【提案】。
  - 部屋1つ = 1マス（扉の奥の小部屋）。部屋と部屋の間を**通路のマス**でつなぐ。行は北（奥）へ、列は東西に並べる。列がずれる所は通路が曲がる（曲がり角・分かれ道・T字路ができる）。
  - 入口のマス（最初の通路）から始まり、北を向いている。
- **地図を作る時に乱数を新しく引かない**【提案】。部屋のつながりから決まった手順で作る（同じ部屋の並びなら必ず同じ地図）。
  - 理由: 乱数を引く順番が変わると、自動プレイの流れが変わり、古い不具合が出る（HANDOFF §7）。また、古い保存データからも同じ地図を作り直せるので、移すのが安全になる。
  - 地図は保存しない（毎回作れる）。保存するのは「位置・向き・見たマス・歩数」だけ。
- データのテスト: 5つのダンジョンと、ランダム生成を種を変えて数百回作り、「マスが重ならない」「全部の部屋に道がある」「ボスまで行ける」を確かめる。

### 3.2 歩く
- 新しいコマンド【提案】:
  - `DUNGEON_STEP { dir: 'forward' | 'left' | 'right' | 'back' }` … その向きへ1マス進む（左・右は「その方向を向いて1歩進む」をまとめた1操作）。**1歩で歩数を1使う。**
  - `DUNGEON_TURN { dir: 'left' | 'right' | 'around' }` … その場で向きだけ変える（**歩数を使わない**）。見回すため。
  - `OPEN_DOOR` … 目の前の扉を開けて部屋に入る（今の `ENTER_ROOM` の中身を使う）。1歩として数える。
- **歩く・向きを変えるのは、手番のキャラの担当の人だけ**【提案】（世界マップの「交代運転」と同じ考え方。ほかの人の画面にも同じ景色が出る）。1歩ごとに全員の投票にすると、4人では遊べないほど遅くなるため。
- **扉を開けて部屋に入るのは、今と同じ全員一致の投票**【提案】。部屋の中身（戦闘など）はみんなに関わるため。投票中に誰かが歩いたら票は無効。
- 世界マップの無いシナリオ（拠点から入る）では、今と同じく歩数の制限なし。

### 3.3 歩数（探索力の判定の使い方）
- 判定は今と同じ（素早さ×2枠・フォーカスで確定成功、2〜4）。
- **歩数 = 探索力 × 2（4〜8歩）**【提案】。`balance.ts` に `dungeonStepsPerExplore: 2` として置く。
  - 理由: 部屋と部屋の間は「通路1マス＋扉1マス」で、だいたい2歩。今の「探索力＝入れる部屋の数」と同じ速さになり、**難しさと1回の冒険の長さ（60〜90分）が今のまま**になる。Gemini の案どおり「2〜4歩」にすると、1手番で1部屋くらいしか進めず、侵食度が今よりずっと進む（実質かなり難しくなる）。
  - 曲がった道・寄り道をすると、その分だけ歩数を使う（寄り道の代償）。
- 歩数が0になり、通路にいる時（部屋の出来事が終わった後）に、次のキャラの番（今と同じ）。「手番を終える」も今のまま。

### 3.4 戻れるか（一方通行か）
- **【提案・推奨】案A「部屋に入ると後ろの扉が閉まる」**: 今いる部屋から次の部屋たちまでの通路は自由に歩ける（見て回れる）。どれかの部屋に入ると、選ばなかった扉は閉じて二度と入れない。今の「選ばなかった部屋には戻れない」と同じ釣り合い。
- 案B「全部自由に戻れる」: 全部の部屋を回れる。宝・経験値が今の約2倍手に入るので**やさしくなる**。代わりに歩数（時間・侵食度）がかかる。釣り合いを自動プレイで調べ直す必要がある。
- → §8 で決めてください。

### 3.5 見えるもの（霧とオートマッピング）
- 入った時は、地図は**入口のまわりしか見えない**。歩くと、**自分の前（2マス先まで）と左右の隣のマス**が「見たマス」として地図に描き足される【提案】。
- **探索度 = 見たマスの数 ÷ 全部のマスの数**（%）。上部に出す。
- **扉の中身（部屋の種類）は、扉が見えた時に分かる**【提案】。spec の「確率は見える化する・部屋の中身は入る前から見える」を守るため、「入ってみるまで何も分からない」にはしない。
  - 戦闘の部屋なら敵の名前とレベル、宝箱の部屋なら箱の種類と確率の帯、は**扉の前に立った時**（今の「部屋をタップ」と同じ情報）。
- **気配（段階C）**: 感知の高いキャラ（例: 感知の成功率が一定以上）・フクロウのお供・探索能力 `sense` を持つキャラがいると、**まだ見えていない1つ先の扉**にも「危険（赤）」「財宝（金）」「静か（青）」の気配の印が出る【提案】。数値（感知いくつから）は段階C の計画で出す。

### 3.6 一人称の絵（段階B）
- **CSS の3D（遠近法の変形）で通路を組み立てる**【提案・推奨】: 壁・床・天井・扉を四角い絵として、奥行き3マス分・左右1マス分を並べる。地図のどんな形（曲がり角・T字・行き止まり）でも自動で描ける。
  - 絵は「壁・床・天井・扉」の**模様（つなげられる絵）を数枚**用意すればよい。絵が来るまではコードで描いた石のような色と線で仮に出す。
  - もう1つの案は「まっすぐ・左に分かれ道・T字…の一枚絵を形ごとに描く」だが、形×ダンジョン5種で40枚以上になり、扉の位置も合わせにくいので推奨しない。
- 演出【提案】: 前進＝奥へ寄るズーム（約0.3秒）、左右＝横に流れる、扉＝左右に開いて暗がりへ入る。松明は小さく揺れる。`prefers-reduced-motion`・設定の「簡易」では短くする。「高速」では半分。
- 演出は見た目だけ。ゲームの結果・保存・同期は待たない（今の移動の演出と同じ分け方）。

### 3.7 画面の並び（段階B・幅360〜480px・文字12px以上）
```

│ 翠の神殿  探索度 34%  所持金 ☰ │ ← 上部（ミニマップと重ねない）
```

- 見本の絵ではボタンの矢印と文字が合っていない所（「前進」に左矢印など）や、下に「周囲の警戒」などのカードがあるが、**それは作らない**【提案】（決まっていない仕組みのため。§8）。
- 大きな地図: ミニマップをタップで全画面。見えた扉をタップ → 「ここまで歩く（あと◯歩）」で自動で歩く【提案】（スマホで何回も押さなくてよいように。自動確認スクリプトも使いやすい）。

### 段階C: 気配・絵と音の差し込み口・仕上げ
- 感知・フクロウ・`sense` による気配。お供の通知（「ホー：何かの気配！」）は今の仕組みを使う。
- **「周囲の警戒」**（オーナー: 面白そう）: 見本の下にあったカード。たとえば「歩数を1〜2使って、まわりの扉の気配（危険・財宝・静か）を調べる」「次の戦闘の奇襲を防ぐ」など。段階Cの計画で案を出して、OK をもらってから作る。
- 絵: `src/assets/art/dungeon/<テーマ>-<wall|floor|ceiling|door>.webp` があれば使い、無ければ仮の絵。Midjourney の指示文を `docs/art/prompts-dungeon.md` に作る。
- 音: K6 で組み込めるよう、鳴らす場所（足音・扉・気配）に名前を付けておく（音そのものは K6）。
- spec.md・STATUS.md の更新。オーナーの実機（Android）で見てもらう。

## 5. 古い保存データ（v14 → v15）
- **【提案・推奨】移す**: ダンジョンの途中の保存は、地図を部屋のつながりから作り直し、
  - 今の部屋がある → その部屋のマスに立ち、北を向く。通った部屋（cleared）とその間の通路を「見たマス」にする。
  - まだ部屋に入っていない → 入口に立つ。
  - 探索力の判定がまだ（`explore == null`）ならそのまま。判定済みなら **歩数 = 残りの探索力 × 2**。
  - 戦闘・宝箱・イベント・休憩の途中なら、その部屋の中のまま（終われば通路に戻る）。
- 地図は保存していないので、作り直すだけで足りる。入口へ戻す案より、遊んでいた人が損をしない。
- テスト: v14 の保存（部屋に入る前・部屋の途中・戦闘中・探索力の判定前/後・場面2つ）を移して、続きが遊べることを確かめる。

## 6. 難しい所・危ない所

| 危ない所 | 対策 |
|---|---|
| 乱数の順番が変わり、自動プレイが別の流れになる | 地図づくり・歩く処理では乱数を引かない。テストが落ちたら、新しい不具合か古い不具合かを先に見分ける。 |
| ローカル協力で、新しい操作が P1 扱いになって P2 以降の番で止まる（前に起きた） | `actorOf` に足し、P2〜P4 の番で歩けるテストを最初に作る。 |
| 1歩ごとの同期が多くなり、オンラインが重くなる | 1歩=1コマンドは今の移動と同じくらいの大きさ。「ここまで歩く」は1コマンドで複数歩にする。 |
| 歩数のせいで1回の冒険が長く/短くなる | `balance.sim.test.ts` の自動プレイで、ダンジョン1つの手番数を今と比べる。違えば `dungeonStepsPerExplore` で合わせる。難しさは下げない。 |
| 地図の自動生成で、部屋の多い行（3部屋）や長い魔王城（9行）でマスが重なる | 全ダンジョン＋ランダム数百回のテスト。 |
| CSS 3D が古い Android で重い・ちらつく | 描くのは奥行き3マス分だけ（四角形30枚ほど）。「簡易」設定と OS の動作軽減で演出を止める。実機で見てもらう。 |
| 360px の幅にミニマップ・ボタン・パネルが入りきらない | 段階B で `check-layout.mjs` に低い画面（360×560）を必ず入れる。 |
| 「ダンジョンを見る」（世界マップの人が見る時）・場面のタブ | 見る人は操作できない（今と同じ `isLocalPlayer`）。景色だけ同じものを出す。 |
| spec の「見える化」との食い違い | §3.5 のとおり、扉の前では今と同じ情報を出す。遠くは霧。spec を書き直す。 |

## 9. 段階Bの詳しい計画（2026-11-08・OK待ち）

段階Aで「歩く仕組み」はできた。段階Bでは**見た目だけ**を作り直す。ゲームの状態・乱数・保存（v15のまま）・同期は変えない。

### 9.1 段階Bでできること
- 画面の真ん中に、**今いる場所から見た一人称の通路**（石の壁・床・天井・松明・奥の扉）が出る。
- 「前進」で奥へ進むズーム、「左へ/右へ/振り向く/扉を向く」で横に回る動き、「扉を開ける」で扉が左右に開いて暗がりへ入る演出が出る。
- 右上に**小さな地図（ミニマップ）**。タップすると段階Aの大きな地図が重なって開き、「ここまで歩く」が使える。
- 上部に探索度。下部に歩数・パーティ（HP）・道具・装備・撤退（今と同じ並び）。

### 9.2 一人称の通路の描き方【提案】
- 部品 `components/dungeon/DungeonView.tsx`（新規）。CSS の遠近法（`perspective` と `rotateY`・`translateZ`）で、**奥行き4マス・左右1マス**の範囲の「床・天井・左右の壁・正面の壁・扉」の四角形を並べる（多くて40枚ほど）。
- 何を描くかは、エンジン側の純粋な関数 `viewSlices(run)`（`dungeonMap.ts` に追加）で決める。「奥行き d・左右 l のマスは通路か・部屋の扉か・壁か」を、**見たマスだけ**から作る。テストで確かめられる（例: 入口で北を向くと正面に扉、曲がり角では横に開いた口）。
- 部屋の中にいる時は、小さな部屋（四方が壁・北に出口の開いた口）を描く。通った部屋の床には種類の印（剣・宝箱・焚き火など）を薄く出す【提案】。
- 松明は、通路の壁に「x＋y が偶数のマス」だけ付ける（乱数を使わず、いつも同じ場所）。小さく揺れる。
- 遠いほど暗くする（奥は闇に溶ける）。ボスの扉は大きく、金の飾り。
- **絵が来るまでの仮の見た目**: ダンジョンの背景の種類ごとに、CSS のグラデーションと線で石・岩・骨・溶岩の色を変える（神殿=緑がかった灰、溶岩の洞窟=赤黒、地下墓地=骨色、魔王城=紫黒、森の洞窟=苔色）。
- **絵の差し込み口**: `src/assets/art/dungeon/<背景>-<wall|floor|ceiling|door>.webp` があれば自動で使う（`import.meta.glob`）。無ければ仮の見た目。絵そのもの（Midjourney の指示文）は段階C。

### 9.3 演出【提案】
| 操作 | 演出 | 時間（通常） |
|---|---|---|
| 前進・左へ/右へ（1歩） | 前へ寄るズーム（左右は先に90度回ってから寄る） | 0.25秒 |
| 振り向く・扉を向く | その場で回る | 0.25秒 |
| ここまで歩く（N歩） | 1歩ずつ続けて再生（1歩0.15秒） | 0.15秒×N |
| 扉を開ける | 扉が左右に開く→暗がりへ寄る→部屋の画面（戦闘など）へ | 0.45秒 |
- 時間は `balance.ts` の `TIMING` に置く。「高速」は半分、「簡易」はズームと回転をやめて短い切り替え（0.1秒）だけ、OS の動作軽減では演出なし。
- **演出の間もゲームの結果はもう決まっている**（世界マップの移動と同じ分け方）。扉を開けて戦闘になる時だけ、扉が開く演出が終わるまで戦闘の画面への切り替えを待つ（`battleStore` に「ダンジョンの演出待ち」を1つ足す。`App.tsx` はその間ダンジョン画面を出す）。演出は端末の中だけで、保存・同期を待たせない。オンラインでも、ほかの人の画面で同じ演出が出る（届いた状態の位置の差から再生）。
- 演出中にもう一度ボタンを押したら、残りの演出を飛ばして次の操作を受け付ける（待たされない）【提案】。

### 9.4 画面の並び（幅360〜480px・文字12px以上・押す所は高さ44px以上）
```
┌─────────────────────────────┐
│ 翠の神殿   探索度 34%  60G   ☰ │ 上部（高さ48）
│┌───────────────────┐┌─────┐ │
││                   ││ミニ │ │ ミニマップ 88×88（タップで大きな地図）
││   一人称の通路      │└─────┘ │
││       （扉）         │       │ 通路の絵（残りの高さを全部使う）
││ ┌扉: 何があるかは…  [扉を開ける]┐│ 扉の前だけ、絵の下に重ねて出す
││ [←左へ][↑前進][右へ→][↶振り向く]│ 歩くボタンは絵の下端に重ねる（半透明）
│└───────────────────┘      │
│ 残り歩数 5 ●●●○ [手番を終える]  │ 歩数（今と同じ）
│ 顔HP 顔HP 顔HP 顔HP  装備 道具 撤退│ パーティ

```
- 歩くボタンを絵の下端に**重ねる**か、絵の**下に並べる**かは §9.7 で決めてもらう。重ねると絵が大きくなる（見本に近い）。下に並べると絵は小さくなるが、文字とボタンが読みやすい。
- 低い画面（360×560）でも、通路の絵が高さ200px以上残るようにする。足りない時は、ミニマップと扉の吹き出しを小さくする。
