### 足りないもの
1. **まだ「六角形のタイル」に見える**【事実】: どのマスも同じ形の六角柱で、上の面の縁に線があり、マスの間に溝が見える。景色がマスの形に閉じている。
2. **森と山がマスごとの飾り**【事実】: 木の位置はマスの中だけ、山はマスごとの三角1つ。隣の森とつながらず、山脈にならない。
3. **高さの差が小さい**【事実】: 段差は最大で半径の42%。山の「大きさ」はほとんど感じない。
4. **遠くの目標が見えない**【事実】: 霧の向こうには何も見えない。「いつかあそこへ」という目印がない。
5. **水がつながっていない**【事実】: 湖・海はマスごとの六角形。岸辺がない。**川という地形はゲームに無い**（17種類の地形に「川」は無く、`water` は湖）。
6. **施設が平たい**【事実】: 町などは1枚の絵を立てているだけ。仮の図は小さい。
7. **霧がどのシナリオでも同じ**【事実】。侵食度は色をかけるだけで、地形は変わらない（侵食度でマスの地形が変わる処理は、エンジンに無い。地形は地図を作る時に決まり、その後は変わらない）。
8. **重さ**【事実】: 地形の層は SVG で、要素がマスごとに10〜15個（全部で数千）。これ以上、木や岩を SVG で増やすと、古い Android で、拡大した時やスクロールで新しい所が見える時の描き込みが重くなる【推測】。

## ③ 独自の提案（冒険のワクワクのため）

1. **地平線の目印**: 地図の上の余白（今は雲だけ）を、遠景の空と地平線にする。最後の城・裂けた火山などの大きなシルエットを、実際の場所の真上（同じ横位置）に、淡く大きく立てる。冒険の初めから「いつかあそこへ」が見える。上へスクロールするほど近づいて濃くなる（空気遠近法）。
2. **辺の木・辺の岩**: 隣り合う2マスが両方とも森なら、その境目の辺に「辺の木」を置く。位置と種類は「2つのマスの番号の組」のハッシュで決めるので、どちらのマスから見ても同じ木になり、自然に1つの森になる。山どうしなら、辺に尾根を置く。
3. **森の中の小道**: 街道が森を通る時は、道の近くの木を取り除き、道の両側に木を寄せる。「森を抜ける道」に見える。
4. **新しい景色の発見**: 霧が晴れた時、晴れた所に目印や山が含まれていたら、カメラを少しだけそちらに寄せて止める（0.6秒。「動きを減らす」では無し）。
5. **夜の町の灯**: 暗い沼の先で町の窓が光る（今の明かりを、町の窓の位置に小さく、数を絞って）。
6. **駒の足元の輪**: 森や山の上に駒がいても見えるよう、駒の下に小さな明るい輪を描く（今の台座に加えて）。駒は今も地形より上の層なので隠れないが、背の高い木の「前」に見えて不自然な時は、駒のいるマスとすぐ手前のマスの木だけ半透明にする。

## ④ 実装方針

### 方式の比べ
| 方式 | 中身 | 良い所 | 心配 |
|---|---|---|---|
| A. 今の絵と CSS だけ | 今の SVG に図を足す | 作りが簡単 | 木や岩を増やすほど SVG の要素が増え、古い Android で重い【推測】。手描きの雰囲気が出しにくい |
| B. 絵のパーツを足して 2.5D を強める | 透明背景の絵（木・峰・施設・目印）を、決まりに従って並べる | 見た目が一番よくなる | SVG の `<image>` を数百並べると、やはり描き込みが重い【推測】 |
| **C. Canvas を一部に使う（おすすめ）** | 動かない景色（地面・側面・道・木・峰・岩）を、Canvas に**前もって1回だけ描いた絵**にする。縦に区切った数枚（雲の海と同じ考え方）。駒・敵・施設・光るマス・霧・明かりは今の層のまま | スクロールは「絵を動かすだけ」なので一番軽い。木を何百本描いても、描くのは霧が晴れた時と拡大を変えた時だけ | 霧が晴れるたびに、その区切りを描き直す（数十ms【推測】）。拡大中（ピンチ）は前の絵を拡大して見せ、指を離してから描き直す |

**おすすめ: B の絵のパーツを、C の Canvas に描く**（B＋C）。WebGL は使わない。

### 層の順番（下から）
1. 遠景（地平線の空・目印のシルエット）… 地図の上の余白。動かない絵
2. **景色の層（新しい Canvas）**… 地面のつながった形・崖・岸辺・道・木・峰・岩。下に書く「描く順番」で並べる
3. 水面のきらめき（今のまま）
4. 雲の海（今の `FogSea`。シナリオごとの色と模様に広げる）
5. 霧の向こうのシルエット（山脈と目印だけ。淡く）
6. 施設のミニチュア（今の FeatureLayer）
7. 時間帯の色・明かり（今のまま）
8. 操作の印（光るマス・経路・旗）、駒・敵（今のまま。いつも一番上）

### 景色の層の作り
- **地面**: マスごとに「少しゆがんだ六角形」（頂点をハッシュで少し外へ）を、地形の絵の模様で塗る。隣のマスとかみ合って、まっすぐな境目の線が消える。違う地形の境目は、ふちを水彩のにじみのような半透明の帯でぼかす。
- **高さ**: 地面は0〜2段（水0・平地と道と森の地面1・丘と山の地面2）。崖（側面）は、手前のマスが低い所だけに描く。高い地形の影を、低いマスに落とす（今の影の帯を広げる）。
- **描く順番（またぎの解決）**: 地面を全部描いた後、木・峰・岩・辺の木などの「立つ物」を、**足元の y（画面の高さ）の順**に、マスをまたいで並べて描く。手前に立つ物ほど後に描くので、隣のマスにはみ出しても重なりが正しい。
- **森**: 1マスに5〜8本（位置はハッシュで少しずらした格子）＋「辺の木」。森の端の辺には木を置かない（森の外側が自然に薄くなる）。森の地面は少し暗くする。道の近くは木を除く。
- **山**: 山のマスに峰の絵（高さはマスの約2倍）。隣の山の数で大きさを変える（山脈の真ん中ほど高い）。山どうしの辺には、2つの峰をつなぐ尾根（プログラムで描く、峰の絵と同じ色の水彩の帯と墨線）。1マスだけの山は「孤立した峰」の絵。
- **丘**: 丸い起伏の絵を1〜2個。
- **平原**: 何もない所を多めに残し、草・花・小岩をまばらに（ハッシュで3割のマスだけ）。
- **水**: 湖・海のマスは低い水面を1つの形として描き、陸との辺に岸辺（白い波の線と砂の帯。プログラムで描く）。
- **道**: 今の曲線を、ハッシュで少し左右に揺らし、森・丘の中では地形を避けるように曲げる。分かれ道はそのまま。
- **侵食度**: 25/50/75% で、ハッシュで選んだマスに亀裂・紫の結晶・枯れ木を増やす（見た目だけ）。

### 守ること
- ゲームの中身（8×28・移動・タップの判定・保存）は変えない。乱数は使わず、マスの番号のハッシュで決める（オンラインでも全員同じ景色）。
- タップは元の六角形の中心で判定（今のまま）。
- 「動きを減らす」では、雲・水・木の揺れなどを止める。

### 変えるファイル（予定）
- 新: `src/components/world/landscape/`（Canvas の景色の層・置き方の決まり・パーツの一覧）
- 変更: `WorldMap.tsx`（層の入れ替え）、`diorama.ts`（高さ・つなぎの判定）、`FogSea.tsx`（シナリオ別の霧・霧の向こうのシルエット）、`MapMiniatures.tsx`（施設の絵の差し替え口）

## ⑤ 絵の制作計画

### 生成する絵と、プログラムで描く物の分け方
| プログラムで描く（絵は要らない） | 生成する絵（透明背景の1つの物） |
|---|---|
| 地面のつながり・ゆがんだ六角形・地形の境目のにじみ | 木（地域ごとの種類） |
| 崖（側面）・影・高い地形が落とす影 | 山の峰（孤立・山脈の中・山脈の端） |
| 尾根（峰と峰をつなぐ帯） | 丘のふくらみ・岩・草・花・キノコなどの小物 |
| 岸辺の波の線・水面 | 施設のミニチュア |
| 道の曲線・わだち | 遠景の目印（大きなシルエット） |
| 雲の海・霧・明かり・時間帯の色 | 侵食の小物（亀裂・紫の結晶・枯れ木） |

**大事な考え方: 「つなぎ」の絵は描かない。** 向きごとの「つなぎのパーツ」（6方向×種類）を生成AIで作ると、向き・光の当たり方・継ぎ目をそろえるのがとても難しい。代わりに、**向きの無い1つの物（木1本・峰1つ・岩1つ）の絵**を作り、プログラムが「どこに・どの大きさで・どの順番で置くか」でつなげる。尾根・岸辺・崖のように向きが要る物はプログラムで描く。

### 絵の決まり（全部共通）
- 透明背景・1枚に1つの物・物は真ん中、**接地点（足元）は下の真ん中**。
- 光は左上から。影は描かない（影はプログラムで描く）。
- 墨線（太さ不均一）＋淡い水彩。輪郭は少し太め（45px でも形が分かるように）。
- 大きさ: 小物 256px・木 384px・峰と施設 512px・目印 1024px 幅。webp に変換して使う。

### ChatGPT と Midjourney、どちらに向くか
| 観点 | ChatGPT（画像生成） | Midjourney |
|---|---|---|
| 透明背景 | 指定すれば透明で出せる【推測：今の画像生成の機能。使う前に確かめる】 | 透明背景は出せないので、切り抜きが要る（`scripts/art/build_art.py`） |
| つなぎのパーツの作りやすさ | 「同じ絵柄で、向きを変えた物を」と会話で細かく直せる | 1枚ごとの絵の質は高いが、細かいそろえは苦手 |
| 絵柄（墨線＋淡い水彩）のそろえやすさ | 同じ会話の中で、見本の絵を渡しながら続けて作れる | スタイルの参照（--sref）でそろえられる |
| 向いている物 | **小さなパーツの量産**（木・岩・小物・施設・侵食の小物） | **大きな1枚の見せ場**（遠景の目印） |

**この設計の分け方は、ChatGPT でまとめて作る案に向いています**（1つの物・透明背景・同じ決まりの繰り返し）。目印のような大きな絵は、どちらでも作れます。新しいお金は使わず、オーナーが今使っているプランの範囲で作ります（商用での使い方の決まりは、作る前にもう一度確かめます）。

絵が来るまでは、プログラムで描いた仮のパーツで動きを作る（今の仮の図と同じやり方）。

## ⑥ 最初の試作計画（はじまりの平原・翠の森）

- 範囲: シナリオ1の下の2つの地域（平原・森）。他の地域と他のシナリオは今のまま。
- 作るもの:
  1. 案B を既定にする（縦 0.68）。
  2. Canvas の景色の層（区切りごとに描く・霧が晴れた区切りだけ描き直す・拡大を変えた時は指を離してから描き直す）。
  3. ゆがんだ六角形の地面・境目のにじみ・低い崖と影。
  4. 森（マスの木＋辺の木・森の小道）。
  5. 平原（まばらな草花・小岩・何もない所）。
  6. 道の揺らぎ。
  7. 施設4種を大きめのミニチュアに（仮の絵 → 絵が来たら差し替え）。
  8. 地平線の目印1つ（侵食の魔王城のシルエット）。
- 確かめること（写真と数字で報告）:
  - 平原と森の高さの違い、木の重なり、道のつながり、施設の立体感、遠景の目印、霧、キャラの見やすさ
  - 拡大1倍・1.5倍・2.5倍の見え方、タップの判定（既存の確認スクリプト）
  - 重さ: `world-perf.mjs`（歩く・止まる、1倍・2倍）と `perf.mjs`、霧が晴れた時の描き直しの時間、使うメモリ
  - 夜・夕方・侵食度75%でも見やすいか
- めやす: 仮のパーツで2日ほど【推測】。絵の差し替えは、絵が来てから半日。

## ⑦ 危険と確認事項

| 心配 | 中身 | 対策 |
|---|---|---|
| 重さ（古い Android） | Canvas の区切りはメモリを使う（390×720px・画素密度2.6で1枚 約7MB【推測】）。拡大2.5倍では区切りが増える | Canvas の画素密度を最大2に抑える。画面から遠い区切りは捨てて、近づいたら描き直す。木や岩は前もって読み込んだ絵を `drawImage` するだけにする |
| 霧が晴れた時の止まり | 区切りの描き直しで一瞬止まる | 晴れたマスを含む区切りだけ描き直す。描き直しの間は前の絵を見せる |
| 見やすさ | 背の高い木・峰が、後ろの行の道や数字を隠す | 立つ物は少し半透明の水彩にする。光るマス・数字・施設・駒は、景色より上の層なので隠れない。駒のいるマスの周りの木は半透明にする |
| タップ | 見た目が隣にはみ出しても、判定は元の六角形 | 今の判定のまま。確認スクリプトで確かめる |
| 描く順番 | マスをまたぐ物の重なり | 足元の y の順に全部並べて描く（④） |
| 制作の手間 | 絵の枚数（全部で約180枚） | つなぎはプログラムで。施設は共通の形＋差し替え。最初は16枚で試す |
| 自動生成との整合 | 森が1マスだけ・山が1マスだけ、道が森を横切るなど | 1マスの森は「木立」、1マスの山は「孤立した峰」の絵。道の近くは木を除く。どの並びでも破綻しないよう、ハッシュの種を変えた写真を何枚も撮って確かめる |
| 霧の向こうのシルエット | 山の位置が少し分かってしまう | 入れるか、オーナーに確認する |
| 見た目だけの川 | 渡れるか分からなくなる | 今回は入れない。入れるならエンジンの仕事として別に計画 |
| オンライン協力 | 全員が同じ景色か | 乱数を使わず、マスの番号のハッシュで決める（今の作りと同じ） |

### オーナーに決めてもらいたいこと
1. 地面の高さは控えめ（0〜2段）にし、山や森の高さは「立つ絵」で出す方針でよいか。
2. 霧の向こうに山脈のシルエットを見せてよいか（通りにくい所が少し分かる）。
3. 川は今回は入れない（入れるならエンジンで川と橋を作る、別の仕事）でよいか。
4. 絵は ChatGPT で、まず試作用の約16枚を作る流れでよいか。
5. 最初の試作（⑥）に進んでよいか。
