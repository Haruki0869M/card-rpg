## 1. 原因（確かめた事と、推測を分けて書きます）

### ① 判定つきイベントの合意と、フォーカスが消える

**確かめた事（コードと再現）**

- 票の「同じ選択かどうか」の目印は、**選択肢の番号だけ**です。「だれが挑むか（heroId）」と「フォーカスの数（focusUsed）」は目印に入っていません（`src/engine/game/votes.ts:42-46` の `voteKey`）。
- 全員の票がそろうと、同じ選択肢に入れた人の中から **「先頭の人」の票**が選ばれ、その票の中身（キャラとフォーカスも込み）でそのまま判定が回ります（`votes.ts:63-79` の `tally`。最後の `return v.picks[by]`）。先頭の人 = ダンジョンの組の1人目のキャラの持ち主（`votes.ts:18-24` の `voteLead`）= **先にダンジョンに入った人**です。
- P2 の画面で同じ選択肢を押すと、サブパネルは「この端末のキャラの中でいちばん得意なキャラ・フォーカス0」で開きます（`src/components/screens/RoomScreens.tsx:86-92` の `choose`、`:21-25` の `bestHero` は自分の端末のキャラだけを見る）。
- **再現（先頭 = P2 の並び）**: P1 が「レオン（力85%）・フォーカス1（成功率98%）」で「挑戦する」→ P2 が同じ選択肢を押して「挑戦する」→ 判定は **P2 の魔道士（力の枠の成功率30%・選択肢の成功率22%）・フォーカス0** で回り、失敗（3枠とも外れ）。P1 のフォーカスは 3 のまま（使われていない）。オーナーの報告と同じ形です。
- 先頭 = P1 の並びでは P1 の指定（フォーカス1）が使われました。つまり「たまたま誰が先に入ったか」で結果が変わります。どちらの場合も、もう1人の指定は知らせなく捨てられます。

**画面の分かりにくさ（確かめた事）**

- P1 が「挑戦する」を押した後、**P1 の画面は何も変わりません**（サブパネルと「挑戦する」ボタンが出たまま）。「みんなの選択を待っています」の枠は選択肢の一覧の中にあり、サブパネルを開いている間は一覧ごと隠れるためです（`RoomScreens.tsx:190-192` の `!opt?.check && options`）。「戻る」を押して初めて待ちの枠が見えます。
- 待ちの状態で同じ選択肢をもう一度押すと、サブパネルが**フォーカス0に戻って**開き直します（`RoomScreens.tsx:89-91` が毎回 `setFocus(0)`）。もう投票したかどうかは、ボタンの中の小さな「P1」の札でしか分かりません。
- サブパネルの「選んだ番号」は画面の部品の中だけで覚えているので、場面が進んでも残る事があります（次のイベントで前のパネルが出たままになる。再現の台本で1度出ました）。

### ③ 「通信が切れています」が何度も出る

**今の決まり（確かめた事）**

| 項目 | 今の値 | 場所 |

**確かめた事（再現）**

- P2 の接続を切ると、P1 に知らせが出るまで **0.02秒**。戻ると 0.1秒で消える。つまり**一瞬の切断でも毎回ちらっと出ます**。
- P2 がつながったまま（「動いている」も書けている）で、接続の印だけが false になると、**P2 は自分で true に書き直しません**。P1 の画面には「通信が切れています（あと22〜33秒で、代わりに操作できます）」が出続け、秒数は減っては戻るの繰り返しです（P2 が動いている限り35秒に届かない）。P2 が扉を押して戦闘が始まっても消えませんでした。オーナーの「P2 が操作中に何度も出る」「あと〇秒」と同じ見え方です。
- 自分の印が false のままだと、ホストの場合は**動いているのにホストを引き継がれる**事もあります（`room.ts:701`）。

**推測（その形になる道筋）**

- スマホが電波を切り替えた・アプリが裏に回った時、端末は新しい接続を作って true と書きますが、サーバーが**古い接続が切れた事に後から気づいて false と書く**と、false が後に残ります（Firebase の接続の印でよく起きる順番のずれ）。LINE 内ブラウザは接続が切れやすいので起きやすい、と見ています。
- タブが裏に回った時: ブラウザはタイマーを遅くします（パソコンの Chrome は1秒に1回 → 5分たつと1分に1回。スマホは止める）。今は「戻ってきた時にすぐ書く」処理がありません（`src/net/` に、画面が見えるようになった時の処理が無い事を確かめました）。戻ってから最大5秒は「止まっている」ままです。

**LINE 内ブラウザの見分け方**

- User-Agent に ` Line/`（例 `… Mobile Safari/537.36 Line/14.9.0/IAB`）が入っています。ほかのアプリ内ブラウザは `FBAN`・`FBAV`（Facebook）・`Instagram`・Android の `; wv)`。今のコードには見分ける処理がありません。

## 2. なぜ今の自動テスト・画面の確認で見落としたか

| 観点 | 見落とした理由 |
|---|---|
| 1. 低い画面高さ | 確認の台本の高さは 780px（32か所）・844px（15か所）・640px がほとんど。560px を見ているのは `check-layout.mjs` の**戦闘の画面だけ**で、シート・イベント・報酬・転職は低い高さで開いていない。さらに共通の点検（`scripts/lib.mjs` の `layoutIssues`）は「スクロールできる枠の中は対象外」「重なりは見ない」ので、カードが画面の下に隠れても、帯が×にかぶさっても通る |
| 2. 「だれが・フォーカスいくつ」込みの合意 | エンジンのテストは「2人が同じ選択肢に入れたら決まる」までで、**先頭でない人が指定を出す形**が無い。自動プレイ（bot）はいつもフォーカス0（`src/engine/bot.ts:587`）。オンラインの台本は、イベントを世界マップ（投票なし）でしか通していない |
| 3. 合意待ち中に別のシートを開く | 台本は「待ち → 相手が押す → 進む」のまっすぐな流れだけ。待ち中にシートを開く・シートを開いたまま通信が切れて戻る・知らせの帯とシートが同時に出る、を1つも通していない。また、P2 の操作の多くは**画面のボタンではなく命令を直接送って**いる（`window.__online.send`）ので、P2 の画面で「押せるか」を見ていない |
| 4. 持ち物と道具袋の役割 | テストの穴というより**設計の穴**。「持ち物 = 渡す所」「道具袋 = 使う所」と分けて作り、「薬を使いたい人が持ち物の一覧を開く」流れを考えていなかった。「やりたい事（薬を使う・物を渡す）から画面をたどる」確認が無かった |

PC が重いので、**1本ずつ流せる小さな台本**に分けます（どれも `heavy.mjs` を通す）。

## 4. 直しの計画

### ① イベントの合意（2回）

**案の比べ**

| | 案A（オーナーのおすすめ）: 先に選択肢を決め、決まってから担当がフォーカスを決める | 案B: 最初の人が指定込みで提案し、2人目は「同意」するだけ |
|---|---|---|
| 分かりやすさ | 宝箱と同じ流れ（開け役を決める → 開け役が決める）。覚える事が1つで済む | ボタンに「レオン・フォーカス1（98%）」と出す必要があり、文字が多い |
| 相談 | 「どれにする？」と「フォーカスいくつ使う？」を分けて話せる | 提案が気に入らない時、別の指定で出し直す → どちらが生きているか分かりにくい |
| 3〜4人・多数決 | そのまま使える | 同じ選択肢で指定だけ違う票が割れた時の決まりが要る |
| 作る量 | エンジンに「決まった選択肢と担当」を覚える所を足す（中くらい） | 目印に指定を入れるだけ（小さい）。ただし画面の作り直しは同じくらい |

**おすすめは案A**です。理由: 宝箱と同じ形にそろう・多数決のまま使える・「勝手に0に戻る」が仕組みとして起きなくなる。

**案Aの中身【提案】**

1. **選ぶ段**: 選択肢のボタンを押すと、**すぐ1票**（判定つきでもサブパネルは開かない）。自分が入れた選択肢は金の縁と「✓ あなたが選択中（もう一度押すと取り消し）」。待ちの枠（P1: 倒木を押しのける／P2: 考え中…）はいつも見える所に出す。決め方は今と同じ（多数決。同じ数なら先頭の人）。
2. **決まった時**: 判定なしの選択肢は、今までどおりすぐ実行。判定つきは、**その判定がいちばん得意な（生きている）キャラ**を「挑む役」として記録して止まる。
3. **挑む段**: 挑む役の持ち主の画面にだけ、フォーカスを決めるパネルと「挑戦する」。ほかの人の画面には「P1 ハルさんが、レオンのフォーカスを決めています（力85%）」。挑む役の持ち主は「ほかのキャラに任せる」で役を替えられる（任された持ち主の画面に移る。宝箱の「任せる」と同じ考え）【提案】。「選び直す」で選ぶ段に戻れる（挑む役の持ち主だけ）【提案】。
4. **払う選択肢**（お金・フォーカス・道具）: 同じ流れで、「払えるキャラ」を払う役として記録し、その持ち主が「払って進む」を押す【提案】（今は先頭の人から黙って引かれる）。
5. 持ち主が切断中の時は、今の「ホストが代わりに操作」でそのまま進められる。
