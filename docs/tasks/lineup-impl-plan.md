### 0-2. 古い保存データ（冒険の途中のセーブ）

今の作りでは、消した装備やカードを持っている保存データは「読めない」と判定されて、**続きから遊べなくなります**。

## 2. 1つの区切りの進め方

1. 区切りの始めに、その区切りで作る物の一覧と「新しい仕組み」を短く説明する（OK は、この計画への OK で兼ねる。**計画と違う事をする時だけ、止まって聞く**）。
2. 新しい仕組みを1つずつ作り、1つずつテストを書く（「この装備を着けて、この場面で、こうなる」）。
3. データを書き換える（外す・変える・足す）。置き換え表も同時に直す。
4. 確認（重い確認は順番待ちの道具を通す）:
   - 型チェック・全部のテスト。
   - 自動プレイ 2人と4人（両方通って成功）。
   - 古い保存データが置き換えで読める事。
   - `docs/review/lineup.md` を作り直して、**「中身が同じ物」が0組**のままである事。
   - 説明文が画面で切れていないか、実際の画面で確かめる。
5. `docs/STATUS.md` に記録、コミット、主ブランチに統合、バックアップ。プッシュはしない。
6. 報告（できた事・できなかった事・自分で判断した所）。**次の区切りは、OK をもらってから。**

## 3. 気を付ける事

| 事 | どうするか |
|---|---|
| **難しさを下げない** | 装備を減らすと、強い物を引きやすくなる事も、引きにくくなる事もある。区切りごとに、前と後で自動プレイの勝率を**記録だけ**する。数字合わせは道のり6。はっきり易しくなった時は、カードを弱めず、止まって相談する（敵を強くする方向） |
| **直行 bot に合わせない** | 憲章の通り。合格の線にしない |
| **乱数** | 種つきの乱数だけ。結果を書き換える物（天穿つ弓 など）は乱数を引かない作りにして、占星術師の「星読み」と食い違わないようにする |
| **1人・ローカル協力・オンライン** | 新しい仕組みは、3つとも同じ結果になる事をテストする。「P2 以降の番で止まる」不具合（前に起きた）が出ないか確かめる |
| **オンライン** | データが変わるので、古い版の人と新しい版の人は一緒に遊べない（今ある仕組みで、自動で分かる） |
| **宝箱の中身** | シナリオ限定の武器が減るので、どのシナリオ・どのジョブでも、持てる武器が各格に1本はある事をテストする。無い格は、1つ下の格から出る（今の作りのまま） |
| **名前** | 能力と合わなくなった名前（一騎銃＝早撃ち など）は、作る時に直す。内部の番号（id）は変えない（保存データのため） |
| **お供** | 動きは可愛く、鳴き声は静かに。お供の行動は全部合わせて1ターン4回まで |
| **説明文** | プレイヤーの目線で、短く（何が起きるか） |
