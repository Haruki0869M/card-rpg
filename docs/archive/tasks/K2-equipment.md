# K2 作業書：武器・鎧・装飾品・消耗品の量産（Codex 向け）

数の目標（docs/design-v2.md §1）と、オーナーが承認した決め方（提案どおり）に沿って、装備を増やす。
**土台（新しい部品・型・検査）は Claude が作成済み。** Codex は「データを書くこと」だけをする。部品が足りない時は自分で作らず、報告に書く。

## 1. 数の目標と今の数

| 種類 | 今 | 目標 | 足す数 |
|---|---|---|---|
| 武器 | 27 | 約190 | 約163 |
| 鎧 | 9 | 約60 | 約51 |
| 装飾品 | 14 | 約120 | 約106 |
| 消耗品 | 6 | 約50 | 約44 |

置き場所: `src/content/common/items/`。**新しいファイルを作る**（既存の `weapons.ts` などは触らない。衝突を避けるため）。
ファイル名の例: `weaponsSword.ts`、`accessoriesFire.ts`、`armors3.ts`、`consumables2.ts`。ファイルは `export const 名前: ItemDef[] = [...]` と書くだけで登場する。

## 2. 守ること

- ID は英数字で重複しない（`data.test.ts` が見る）。**一度出した ID は変えない**（保存データが使う）。
- 画面の文言（`name`・`description`）は、やさしい日本語で短く。英語の用語を出さない。
- 乱数・`Math.random` は使わない。ジョブ ID で分岐する能力は書かない。
- **エピック以上は `ability` 必須**。鎧はレア以上なら必ず固有の効果（`ability` か `explore`）を持たせる。
- 能力値だけの装備はコモンかレアにとどめる（エピック以上は能力が主役）。
- 武器の `weaponType` は 15 種（剣・刀・斧・拳・杖・魔導書・鎌・槌・槍・錫杖・弓・短剣・鞭・銃・楽器）から選ぶ。
- **武器の専用カードは新しく作らない（承認済みの方針）。** 種類×レア度で既存の武器カード（`w` で始まるカード、`weaponCards.ts` など）を共有する。差は能力値・`ability`・`tags`・`focusMax`・`startBlock` で付ける。どうしても足りない時だけ、新しい武器カードを最大約30枚まで（別ファイル `weaponCards3.ts`。K1 の担当と重ならないよう、事前に Claude に知らせる）。
- `tags` を付ける（例: `['fire']`・`['poison']`・`['single']`）。報酬のスマート抽選で、相性の良いカードが出やすくなる。既存のタグ名（`engine/game/cardTags.ts`）に合わせる。
- 絵は作らない。`icon` は既存のアイコン名（`src/art/items.tsx`）から選ぶ。

## 3. 数値の基準（既存の値から決めた目安。変える時は理由を書く）

| レア度 | 武器の能力値 | 鎧の最大HP | 装飾品 |
|---|---|---|---|
| コモン | なし〜+2 | 3〜5 | 能力値+10 |
| レア | +4〜5 | 6〜10 | 能力値+8、またはフォーカス最大+1／ドロー+1 |
| エピック | +8 と特殊能力 | 8〜15 と特殊能力 | 特殊能力が中心 |
| レジェンド | +10〜12 と強い特殊能力 | 20〜25 と強い特殊能力 | 同じ |

難易度は今のまま（難しめ）。強すぎる効果（倍率1.5倍超が常に働く等）は書かない。条件付きなら1.3倍前後まで。

## 4. 並べ方のルール（同じレア度×同じ種類のなかに型を並べる）

武器は、各武器種の**レア・エピック・レジェンドの各段階に**、次の4型を1本ずつ入れる（既存の武器が埋めている型は新しく作らず、そのまま数える）。**コモンは1〜2本で、型は問わない。** これで1種類あたり13〜14本（既存を含む）になり、全体で約190本に収まる:
1. 火力型（能力値が高い）
2. 属性型（`ability` で属性を付ける。例: 完全成功で火傷2）
3. 状態異常型（毒・脆弱・凍結などを付ける）
4. スロット数型または特殊能力型（貫通・連携・吸収など）

装飾品は、次のテーマで3つの束に分けて書く:
- 火力・属性・状態異常
- 防御・回復・フォーカス
- お供・探索・運

## 5. 使える部品

`docs/adding-content.md` の「特殊能力の書き方」「効果の部品」に加えて、K2 で次を足した:

**条件（`if`）**
| 値 | 意味 |
|---|---|
| `selfStatus` `{ status, min? }` | 自分が状態異常を持っている間 |
| `selfHpAtLeast` `{ pct }` | 自分のHPが○%以上（100 = 満タン） |
| `foeCount` `{ min?, max? }` | 生きている敵の数（`max: 1` = 1体だけ） |
| `cardCost` `{ min?, max? }` | 使ったカードのコスト |
| `cardSlots` `{ min?, max? }` | 使ったカードの枠数 |
| `hasPet` | お供がいる間 |

**効果（`do`）**
| kind | 内容 |
|---|---|
| `blockFromStatus` `{ status, of?: 'foes' \| 'self', mult?, max? }` | 状態異常の量だけブロック（例: 敵全員の毒の合計） |
| `convertStatus` `{ status, into }` | 状態異常を別の状態異常に変える（量は同じ） |
| `retaliate` `{ amount, element?, perTurn? }` | （K4で追加）`when: 'hurt'` の能力で、攻撃してきた相手に反撃する |
| `drainFocus` `{ amount }` | （K4で追加）敵の行動で、味方のフォーカスを奪う（0より下にならない） |
| `summonEnemy` `{ enemy, count?, uses? }` | （K4で追加）敵が敵を呼ぶ。戦場4体まで・1戦闘 uses 回（既定2）・呼ばれた敵は報酬なし |

**常時型（`modifier`）**
| modifier | 内容 |
|---|---|
| `elementGuard` `{ element, mode: 'immune' \| 'absorb' \| 'half' }` | 敵の属性攻撃を、無効・吸収（その分回復）・半分にする |
| `convertElement` `{ into }` | 属性の無い物理攻撃を別の属性にする |

**装備の項目**
- `explore: { vision?, campHeal? }` … 世界マップで視界+N、野営の回復の割合+（0.25 = +25%）。鎧に付けやすい。
- `scenario: 'シナリオID'` … そのシナリオの冒険の宝箱・ショップにだけ出る。シナリオ固有の装備に使う。
- `tags`・`ability`・`stats`・`maxHp`・`focusMax`・`startBlock`・`extraDraw`・`cards`。

**まだ無い部品（使わない。必要なら報告に書く）**: 状態異常を付けた時・ブロックが割れた時のきっかけ、お供が2回動く、スロット+1、コスト-1。Claude が作る。

## 6. 見本（ここを真似る）

## 7. バッチの分け方と報告

| バッチ | 内容 | 数 |
|---|---|---|
| 武器1〜5 | 3種類ずつ（剣・刀・斧／拳・杖・魔導書／鎌・槌・槍／錫杖・弓・短剣／鞭・銃・楽器）。武器1・2は完了 | 各約33 |

各バッチの手順: 書く → `npx tsc --noEmit` → `npx vitest run` → 次のバッチの前に Claude がレビューする。
報告に書くこと: 追加した数、数値の基準から外れた物とその理由、部品が足りず書けなかった案、テストの結果（失敗は正直に）。
