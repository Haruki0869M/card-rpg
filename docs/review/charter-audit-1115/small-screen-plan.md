## 2. 見つけた事（重い順）と、直し方の案

### 重い（実装の前に計画書を直す）

**1. 低い画面で通しで遊ぶ確認が無い（憲章7）**
- `scripts/adventure.mjs:130` は 360×640 固定。640 は「ふつう」の側なので、自動プレイは低い形（1段のボタン・畳んだ札・🔍）を1度も通らない。計画 §5 の「端のマスで止まらない」は、ふつうの形だけの確認になる。
- 案: 自動プレイを **390×540 で2人を1本**（できれば4人も1本）足す。オンライン2台の台本（`coop-*.mjs` のどれか）を 390×540 で1本通し、**P2 の端末で、相手の番の間に 💀・🔍・状態の一覧 が開けて閉じられる**事を見る。1台で2人は、受け渡しの画面（`HandoffOverlay` z-50）の後に同じ3つが押せる事。
- 自動プレイは `button:has-text("移動する")`（`adventure.mjs:317`）など字で押している。1段にまとめる時に字を短くすると台本が止まる。字を変える所は計画に書く。

**2. 項目1は、ふつうの画面の見た目も変える（計画の言い方と食い違う）**
- 右の余白 72px と「カメラがボタンの列を避ける」は 390×844 でも効く（地図は横に 337px 動かせる広さなので、手番の駒がいつも 32〜36px 左に寄る）。回2の後は「390×844 の写真に差が無い事」（§5）が必ず落ちる。
- 案A: カメラは今のまま真ん中。**駒・選んだマスが列の下に入る時だけ寄せる**（端のマスの時だけ見た目が変わる）。案B: いつも寄せる。どちらにしても**オーナーに聞く事に足す**（Q6）。§5 の写真の比べ方は「回1・回3 は差なし。回2 は端のマスだけ差」と書き直す。
- あわせて確認: いちばん小さい拡大（`minZoomFor(size.width, w.width)`。`WorldMap.tsx:355`）は「地図全体が1画面」のはず。右に余白を足すと、いちばん小さい拡大でも横に 72px 動くようになる。見取り図・ピンチの残す点（`anchorScroll`）・端の矢印（`edgeArrow`）は左が原点なので、右だけの余白なら座標はずれない見込み（読みだけ）。

**3. 「次の目的」の行の 700px の線が、`data-low` と食い違う**
- `WorldScreen.tsx:197`（`min-height:700px` で出す）・`:661`・`:668`（`max-height:699.98px`）は CSS の高さ。計画 §2 が言うとおり LINE では CSS の高さが見えている高さより大きい事がある。その時、低い形（`data-low`）なのに 44px の行が出て、下の短い「次:」は出ない。計画の勘定（上52＋仲間48）が 44px 狂い、地図は 156px になる。
- 案: `data-low` の時は、この3か所を必ず「低い側」にする（`[data-low]` で上書き。ふつうの画面の線は触らない）。台本で **390×720 の画面に `visualViewport.height = 540` を偽って**、低い形になる・目的の行が出ない、を確かめる（Playwright はふつう両方が同じ値なので、偽らないと見つけられない）。

**4. 災厄の札は世界マップ以外にも出ている**
- `ScourgeStrip` は `WorldTopBar` の中（`WorldScreen.tsx:137`）。`WorldTopBar` は `Places.tsx:95・310・683・715`（町・神殿・祠など）でも使っている。仲間の列（`PartyRow`）は世界マップだけ。
- 低い画面の町で札を消すと、「店+25%」がいちばん大事な場面で見えない。
- 案: 町などの画面は今の札のまま（計画に1行書く）。または上の帯の中に 💀 のボタンを置く（どの画面でも同じ場所）。Q2 に「町の画面ではどうするか」を足す。
- 既存の台本7本（`scourge-7b/7c/hints`・`coop-talk`・`detour-value`・`guide-r1`）が `[data-scourge-strip]` を押している。低い形のボタンにも同じ印を残す。

**5. 下のパネルの低い形の表に、入っていない物がある**
- 野営のボタンの中の **夜襲の%** と **💀回復半分**（`WorldScreen.tsx:825-826`）: 野営するかを決める情報。右の小さいボタンに入るか書いていない。
- 「サイコロを振る」の中の **街道ボーナス +1 の札**（`:782`）。
- **「同行を解除して単独行動する」**（`:699`。44px＋余白）・**「〜を助け起こす」**（`:795-808`。1人につき 48px）: 337px の内訳にも、低い形の表にも無い。本当のいちばん混んだ時は「同行の行＋入る」より高い。
- 振った後の1段「行き先・★振り直す・野営・終える」: 360幅だと中身は 336px、4つで1つ約80px。今の字（「光るマスをタップして行き先を選ぶ」15字・`moveButtonText` の字）は入らない。
- 案: 表に上の4つを足す。「入らない時は2段に戻す（その時の地図は○px）」を先に決める。字を短くする所は一覧にしてオーナーに見せる（「手番を終える」→「終える」など。前に「どこを押せば分からない」と言われた所なので）。

**6. 寒さ・温泉の全文の行き先**
- 計画: 「全文はマスの説明と温泉のヘルプ」。でも `tileInfo`（`WorldScreen.tsx:345-379`）は気候を出していない。短い札（「❄寒さ」）だけになると「毎ターン体力が減る・野営で防げる・回復は半分」が読めない。
- 案: 札を押すと全文が出る（44px の当たり・この端末だけ）。または `tileInfo` に気候の1文を足す（その時は見つけた事 9 の帯がさらに高くなる）。

### 中くらい（計画書に決まりを足せば良い）

**7. 切り替えのばたつき**
- 境目に幅が無い。見えている高さが 640 前後の端末（例: 360×720 の端末でアドレスバーがある時）は、帯の出入りで 639↔640 を行き来し、遊んでいる最中に形が切り替わる（パネルの高さが変わるので、カメラもすぐ合わせ直す = 地図が跳ぶ）。
- `useAppHeight.ts:42` は入力が終わった時（focusout）にすぐ測る。キーボードが閉じ切る前だと低い値が入り、一瞬だけ低い形になる（今は高さが一瞬縮むだけで済んでいる）。
- `useLowScreen()` を effect の中で入れると、最初の1コマが「ふつうの形」で出てから切り替わる。
- 案: **入る線と出る線を分ける**（例: 640 未満で低い形に入り、672 以上で戻る）。最初の値は描く前に決める（`useSyncExternalStore` か、最初の state を測った値で作る）。テストに「639→641→639 で切り替わらない」「入力中・拡大中は前の値」を足す。回転は切り替わって良い。
- 丸め: `visibleHeight` は四捨五入（639.6 → 640 = ふつう）。CSS の `639.98px` の線とは 0.5px ずれるが、実害は無い。

**8. 4人・狭い幅の仲間の列**
- 360幅・4人: 顔 44×4 ＋ すき間 ＋「ステータス」のボタン（約107px）＋ 💀（44px）＝ 約 370px で、はみ出すか「ステータス」がつぶれる。台本は2人だけ。→ 4人の 360×520 を台本に足す。

**9. 見えている地図の上に重なる物が、200px の勘定に入っていない**
- マスの説明の帯（`data-tile-info`。`WorldScreen.tsx:582-586`。12px の字で3〜5行 = 56〜88px。押しても地図に通るが、絵は隠れる）と、扉が開かない時の知らせ（`gateNote`。`:589-602`。ボタン2つ縦で約100px）は、パネルのすぐ上 = 見えている地図の中に出る。地図 200px のうち半分近くが隠れる事がある。
- 一緒に動く提案の窓（`MoveProposal`）はパネルの箱の中（`:606`）なので、パネルの高さに足される（計画は 80px と書いているが、200px の勘定には入っていない）。
- 案: 台本に「マスの説明が出ている時に、手番の駒と選んだマスが隠れない」を足す。低い形の説明は3行まで（残りは「…」）などを決める。

**10. 拡大のボタンの形が場面で入れ替わる**
- 今の決まりは「見えている地図が 279px 未満なら横の列」（`WorldMap.tsx:431`）。低い形の地図は 200〜300px なので、**1人で野原（300px）は縦の列、町の上（200px）は横の列**と入れ替わる。計画の「低い画面では 見取り図＋🔍 に畳む」が、279px の決まりとどう組むか書いていない。
- 案: 「低い画面は、いつも右上の畳んだ形」と書く。端の矢印を置く範囲（`:1164` の `compactZoom ? 82 : 60`・右 90px）・見取り図の最初の案内の向き（`:1206`）も同じ条件に合わせる。🔍 を押して出る ＋・標準・− の**出る場所・閉じ方**（外を押す／もう1度押す）も決める（出たままだと、また 206px をふさぐ）。既存の台本（`world-zoom.mjs`・`place-tap-r1b.mjs`）は `[data-zoom-in]` などを直に押すので、ふつうの形では印を変えない。

**11. 状態の印（Q3 の聞き方が足りない）**
