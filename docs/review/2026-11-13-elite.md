## 1. 作った物

### 柱1 強敵の本気（`src/engine/battle/intents.ts` の decideIntent・frenzyReady・strongestAttack）

- 対象 = 「強敵の本体」。敵の組を決める所（`dungeon.ts` の rollEnemies）で、`pools.elite` の組から来た敵にだけ `eliteBody` の印を付ける。
  - 4行目から足されるふつうの戦闘の敵1体には付かない（組の後ろに足すので、組の数で分ける）。
  - 封魔の宝箱の番人も `pools.elite` の組なので本体（対象）。
  - 町を襲う敵は、部屋の種類は「強敵」だが、敵は地域のふつうの徘徊の組で、印が付かない（対象外）。
  - ボス・中ボスの戦闘では、印があっても本体にしない（createBattle で、戦闘の格が強敵のときだけ印を残す）。
- 本気になる時: **予告を決める時**（戦闘の始めと、敵の番の終わり）に、本体のHPが最大の半分（`BALANCE.eliteFrenzy.hpBelow` 0.5）を切っていて、まだ本気になっていなければ。1戦闘に1回（`frenzyUsed`）。
  - **今の予告は書き換えない形を選んだ。** 予告は敵の番の終わりにだけ決まる作り（intents.ts の decideAllIntents）なので、味方の番に半分を切っても、今見えている予告はそのまま実行され、その次の敵の番の予告から本気になる。こうすると、どの時点でも「見えている予告と違う行動」が起きない。お供の先読み（「次: ○○」）が出ている時は、先読みの行動を先に守り、本気はその次の予告になる。
  - 本気の前に倒しきれば、本気は出ない（火力のご褒美）。
- いちばん強い攻撃の決め方（`strongestAttack`）: その敵の今の行動の一覧から、ダメージの効果の「量 × 回数」の合計がいちばん大きい行動。味方全員への攻撃は、今生きている味方の人数を掛ける。同じ点なら大技（BREAK できる）を先に、それでも同じならデータの順で先の物。手数読み・ブロック・状態異常は数えない。今は意味の無い行動（かばう相手がいない・呼べない）は選ばない。乱数は使わない。
  - 例: 門番ガルザ = 2人なら「大斧の一撃 24」、3人以上なら「大旋風 11 × 人数」。
  - ダメージの行動を1つも持たない敵は本気にならない（強敵の組の敵は、全員ダメージの行動を持つ事をテストで確かめた）。
- 威力: `nextActionMultiplier`（BREAK・時の砂時計と同じ入れ物）に ×1.5（`BALANCE.eliteFrenzy.power`）。予告の数字にも、実際のダメージにも同じに掛かる。BREAK すると ×0.5 が重なる（×0.75）。大技でない行動は BREAK できない（今の決まりのまま）。凍結・時間停止で休ませると、本気はそのまま使い切り。
  - 注意: 今の入れ物の作りのまま、行動の「量」の全部（ダメージだけでなく、その行動のブロック・状態異常の数）にも ×1.5 が掛かる（BREAK の半分と同じ作り）。
- 画面: 予告の枠に橙の「🔥本気」の札（紫の札・赤い大技の札と違う色。枠の縁も橙）。札の下に「威力×1.5」（特殊な行動と重なる時は「HPの低い味方を狙う・威力×1.5」のように1つにまとめる）。敵が3体以上の時は、今日入った「敵の列の下の1行」に出す（本気の時は橙）。長押しの説明の先頭に「🔥本気: HPが半分を切って本気になった。次の攻撃は1.5倍。BREAK するか、守りを固めるか、その前に倒すか」。BREAK 後は札と案内が消え「⚡BREAK」に替わる。ログに「🔥○○は本気になった！」。
- 保存: 印・本気の済み・本気の予告は戦闘の状態に入るので、保存して再開しても・オンラインでも同じ（テストで JSON に書いて読み直して確かめた）。古い保存の、もう作られたダンジョンの部屋には印が無いので、そのダンジョンを出るまでは本気・HPの倍率が付かない（入り直すと付く）。

## 3. 柱3 で作れなかった7か所（→ オーナーが案イを選び、§10 で直した）

翠の神殿（休憩 → ボス）と、2つ目の鍵の型の6か所（沈んだ聖堂・海賊の隠れ島・影の書庫・星見の天文台・蒸気の発電所・砂の幻影の墓。休憩 → 物語の部屋 → ボス）は、今の決まりを全部守ったままでは、強敵を通らない道を作れない。

- 理由（`dungeonShape.test.ts` の決まりから）: 「5行目（敵が1体増える行）から休憩の前まで、どの道でも戦う部屋が2つ以上」。この7か所は休憩の前の奥の行が **5・6行目の2行だけ** なので、その2行は、どの道でも戦う部屋（戦闘か強敵）になる。さらに「同じ type が続かない」ので、2行は必ず「戦闘→強敵」か「強敵→戦闘」。だから、どの道でも強敵を1回通る。部屋の置き方をどう変えても、この2つの決まりがある限り避けられない（中ボスは最後のダンジョンだけ）。
- 物語の部屋（2つ目の鍵の型）は「戦いが始まる！」とボスにつながる文なので、ボスの直前から動かせない。
- 直すには、どれか1つを変える必要がある【提案・未着手】:
  - 案ア: この7か所だけ「奥の戦う部屋」を1つ以上に緩める（例: 5行目の戦闘 → 6行目の宝箱 → 休憩）。道中の戦闘が1つ減る道ができる。
  - 案イ: 休憩を1行前に出す（翠の神殿は「休憩 → イベント → ボス」、1つ目の鍵の型と同じ形）。奥の行が1行になる。
  - 案ウ: 今のまま（この7か所は「強敵を必ず1回」）。

## 5. 読み取れる事

1. **本気は、ほぼ毎回の強敵の戦闘で出る**（強敵の戦闘1つにつき 1.0〜1.35回。1回より多いのは、本体が2体の組があるため。×1.2 でも出る）。どの bot も、本気の約6〜7割を BREAK している。山場（本気の一撃をどう受けるか）は、どの段でも起きている。
2. **強敵の戦闘は長く・危なくなった。** ×1.5 で、強敵の戦闘のラウンドは main より 2人 +0.9〜1.5・3人 +0.7〜1.1・4人 +0.7〜1.1。強敵で倒れる味方・強敵に負けた戦闘は、直行 bot（2人 16→23・3人 15→38・4人 30→69）と工夫 bot（0〜1 → 4〜12）ではっきり増えた。賢い bot は、4人で 0→4 だけ。
3. **「全滅（ゲームオーバー）」は、工夫・賢い bot ではほとんど増えない**（工夫 bot 4人で1回・狩人＋僧侶 1→3）。強敵に負けても命の灯火が残るので、ゲームオーバーまでは行かない。直行 bot は前から全滅で負ける。**「負けが時間切れだけでなく全滅にも出る」は、賢い bot ではまだ起きていない。**
4. **強敵を選ぶか避けるかで、結果は変わる。** 賢い bot が強敵を選ぶと（選ぶ割合 20% → 53〜80%）、強敵の装備は約1.7〜1.8倍・エピックは 0.9〜1.8倍（狩人＋僧侶だけ増えなかった。40種なのでぶれがある）。代わりに戦闘が増え（+1.8〜2.6戦）、時間を使う。強い組ではクリア率はほぼ同じ（98〜100%）だが、時間に余裕の無い狩人＋僧侶では **80% → 57%（侵食度100% が 8 → 15）** に落ちた。「挑めば得をするが、時間を失う」という差が、bot の数字に出ている。
5. **賢い bot のクリア率は、どの段でも 95〜100%（狩人＋僧侶だけ 57%）。** オーナーの目安（回復役入りで約15%、40%でも可）には、強敵だけでは全く届かない（計画どおり、強敵だけで届かなくてよい）。HPの段の差（×1.2〜×1.5）は、20種ではクリア率にほとんど出ない。
6. 柱3 で道を作れたのは沈黙の地下墓所だけなので、シナリオ1では翠の神殿で今も強敵が避けられない（扉が強敵だけの場面「強敵しか無い扉」は、賢い bot で 1冒険あたり約3回）。

## 6. おすすめのHPの段: ×1.5（`balance.ts` の既定にした）

- 理由: ×1.2・×1.3 では、強敵の戦闘のラウンドが main と比べて +0.1〜0.4 しか伸びず、倒れる味方・強敵に負ける戦闘がほぼ増えない（賢い bot 4人で 8・1、負け 0）。×1.5 だけで、強敵の戦闘が「1ターン目で終わらず、本気を受けてから倒す」長さ（2人 5.5・3〜4人 3.6〜3.8ラウンド）になり、4人で倒れる味方・強敵に負ける戦闘が出た。オーナーの「難しめが良い」に合う、計画の範囲（×1.5 まで）のいちばん上。
- 本気が出るかだけなら ×1.2 でも出る（計画の「本気が見える所まで残る最小の数字」の考えなら ×1.2）。おすすめは、難しさを優先して ×1.5。

## 7. 心配な点

- 本気の ×1.5 は、行動の量の全部に掛かる（ブロック・状態異常の数も増える）。今の BREAK の半分と同じ作りなので、そのままにした。
- 4人では、本気の ×1.5 が4人の攻撃の倍率（1.8）と重なる。直行 bot 4人で強敵の戦闘の倒れる味方が 1戦あたり 0.82 → 1.32 になった。工夫・賢い bot では 0.15・0.06。
- 強敵を選ぶと時間を使うので、時間に余裕の無い組（狩人＋僧侶）は、強敵を選ぶほど侵食度100%で負ける。人が遊ぶと「強敵を選んで時間切れ」が増えるかもしれない。
- 翠の神殿・2つ目の鍵の型では、強敵がまだ避けられない（§3）。

- シナリオ2〜7・むずかしい・やさしいは測っていない。オンラインの2台では本気の画面を確かめていない（状態は保存・同期される物だけで作った）。

- 本気の札の画面は、保存データを書き換えて作った場面で撮った。実際の流れで本気になる所は、テストと bot の測定（本気の数）でだけ確かめた。
