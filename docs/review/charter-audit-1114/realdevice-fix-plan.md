## 2. 見つけた事（重い順・直し方の案）

### F1（重い）①の新しい操作が「キャラを指定しない操作は P1 扱い」になりうる

- **なぜ**: 画面から出る操作は `actorOf`（`src/store/battleConfig.ts`）でプレイヤーを決めます。命令に `heroId`（か `userId`・`fromHeroId`）があればその持ち主、無ければ、1台で遊ぶ時は「最初のキャラの持ち主（= P1）」になります（ダンジョンの中では場面の担当が決まらないため）。
  - 「選び直す」（キャラの番号なし）: 挑む役が P2 のキャラだと、1台で2人の時は P1 として送られ、エンジンが「挑む役の持ち主ではない」と断る → **戻れない**。オンラインでホストが P2 の分を代わりに操作している時も、自分の席（P1）で送られて断られる。
  - 「ほかのキャラに任せる」: 命令の `heroId` に**任せる先**を入れると、任せる先の持ち主として送られる。エンジンが「今の挑む役の持ち主か」を見ると断られる。
- **直し方の案**: 計画書に命令の形を書く。
  - 挑む段の命令は3つとも **`heroId` = 今の挑む役**を必ず入れる（任せる先は `toHeroId` など別の名前）。こうすれば `actorOf` を変えずに、1台・オンライン・代わりに操作の全部で正しい持ち主になります。
  - エンジンのテストに「1台で2人・挑む役が P2 のキャラ」で、挑戦する／任せる／選び直す の3つが通る事、を足す。`coop-agree.mjs` に「ホストが P2 を代わりに操作して、挑む段を進める」を1回足す。

### F2（重い）版の違う2台で、黙って止まる

- **なぜ**: 部屋に入る時の版の見分けは「保存の版」と「データの指紋」だけで、エンジンの動きの違いは見ません（`room.ts:251`・`src/data/contentVersion.ts`）。計画どおり版を上げないと、
  - 古いホスト × 新しい相方: 相方が判定つきの選択肢を押すと、古いエンジンが「判定するキャラを選んでください」と断る → **何度押しても票が入らない**（文も的外れ）。
  - 新しいホスト × 古い相方: 知らない命令が届く → 古い側は「ずれた」と見て取り直し → また同じ → **黙って繰り返す**。
  - Firebase Hosting は `firebase.json` に設定が無いので、`index.html` が端末に最長1時間ほど残ります。LINE 内ブラウザは特に残りやすい。**公開の直後に2台の版が違うのは、ふつうに起きます**（⑤の「1回で即決まる」が再現しなかった理由の候補に、計画書自身が「古い版が残っていた」を挙げています）。
- **直し方の案**（どれか。おすすめは A）:
  - A: 取り直しが同じ番号で2回続いた時・「知らない命令」で断られた時に、**「ゲームの版が相手と違います。2台ともページを読み込み直してください」と画面に出す**（小さい。進行中の部屋は生きる）。
  - B: エンジンの決まりの番号（例 `RULES_REV`）をデータの指紋に混ぜる。古い版は部屋に入る時に「読み込み直してください」と出る。ただし**公開の前に作った進行中の部屋には、新しい版では戻れなくなる** → これはオーナーに聞く事（§5 の追加1）。
  - どちらの場合も、公開の知らせの1行は残す。

### F3（重い）③の猶予で、ホストの引き継ぎの速さが変わる

- **なぜ**: 今は「接続の印が false」になった瞬間に `alive` が false になり、次の人が**すぐ**引き継ぎます（`room.ts:187-189`・`:697-709`）。35秒かかるのは「接続は残ったまま眠った」時だけです。計画の「false でも、最後の『動いている』から15秒以内なら生きている扱い」を入れると、
  - ホストがタブを閉じた・電波が切れてサーバーが気づいた・**「部屋を出る」を押した**（`leave()` も false と書く。`room.ts:369`）時も、引き継ぎが **5〜15秒＋見回りの最大5秒** 遅れます。
  - 計画書の「本当に切れた時の…ホストの引き継ぎ（約35秒）は変えません」と食い違います。今あるテスト（`room.test.ts`・`online.mjs` の「切断 → 引き継ぎ」）が「すぐ」を前提にしていれば落ちます。**テストを通すために決まりを変える形にならないよう、先に決めておく**必要があります。
- **直し方の案**:
  - 「部屋を出る」は猶予なしにする: `leave()` で `beat` も 0 と書く（自分の `members/{uid}` の下なので、ルールは変えずに書ける）。
  - ふつうの切断は「最大15〜20秒遅れる」と計画書に正直に書き、オーナーへの説明に入れる（一瞬の切断で引き継がない事との引き換え）。猶予の秒数は 15秒でなく **10秒**（=「動いている」を書く間隔）でも目的は果たせます【点検役の提案】。
  - テストに「本当の切断は N 秒以内に引き継ぐ」「出た時はすぐ」「一瞬の切断では引き継がない」の3つを並べる。
- 書き込みの量: 印の書き直しは「false を見つけた時だけ」なので増えません。念のため「閉じた後・切断中は書かない」「2秒に1回まで」と書いておくと安心です。画面が戻った時の書き込みも回数は少ない。**問題なし**。

### F4（中）LINE の案内に従うと、席を失う

- **なぜ**: 端末ID（匿名ログイン）はブラウザごとです。LINE 内ブラウザで部屋に入った後に「ほかのブラウザで開く」をすると、**別の人**になります。待合室なら空いた席に入り直せますが、元の席と作ったキャラは「いない人」として残ります。冒険が始まった後は「この部屋はもう冒険を始めています」で**入れません**（`room.ts:254`）。
- **直し方の案**: 案内は**部屋に入る前**（タイトル・「部屋に参加」の画面）だけに出す。待合室で出すなら「キャラを作る前に」と書き、冒険中は出さない。招待リンクの `openExternalBrowser=1` は「最初から外で開く」ので、この問題を避ける良い手です（実機で確かめてから、は計画どおり）。

### F5（中）①の決まりで、書いていない所

1. **お金（や道具）も判定もある選択肢**: 今は「挑むキャラが払う」（`game.ts:1306-1313`）。「いちばん得意なキャラ」がお金を持っていない事がある → 挑む役は「払えるキャラの中でいちばん得意」にする、「任せる」先も払えるキャラだけ、と書く。
2. **払えるキャラが複数**: だれを払う役にするか（場面の並びの先頭・いちばんお金を持つ人 など）と、「ほかのキャラに払ってもらう」を付けるか。お金はキャラごとなので、**だれの財布から出るか**は遊びの決まりです → オーナーに聞く事（§5 の追加2）。
3. **今ある同じ種類の不具合（計画書に無い）**: 払う選択肢は、票を入れる時に「その人のキャラで払えるか」を確かめています（`game.ts:326` の試し実行 → `:1307-1308`）。ボタンは「だれかが払えれば押せる」表示なのに、**払えない人は票を入れられず**、先頭の人が払えない人だと、その選択肢は決まりません。案Aの4で直りますが、`coop-agree.mjs` に「払えない人も、払う選択肢に票を入れられる」を足してください。
4. **挑む役がその場からいなくなった時**（後から仲間が合流・キャラが場面を離れる・倒れる）: 命令を受けるたびに挑む役を確かめ、だめなら自動で選び直すか、選ぶ段に戻す、と書く。
5. **いちばん得意が同点の時**: 場面の並びの順（端末によらない決め方）と書く。
6. **挑む段の間に届いた古い票**: 断る。場面の目印（`voteCtx`）に「決まった選択肢」を入れる（計画の「互換」の所から読み取れますが、はっきり書く）。
7. 今は票の中で**ほかの人のキャラを挑む役に指定でき、その人のフォーカスを使える**作りです（`game.ts:321-324`）。案Aで無くなるので、良い副作用です。

### F6（中）取り直しの後もシートを残す時の安全

- エラー境界が無い事は計画書も確かめています。シートは「選んだ道具・キャラ」を画面の中で覚えているので、取り直しでその道具が無くなっている（相方が代わりに使った・渡した）と、落ちる危険があります。今も「だれに渡す？」の枠は、見つからない時に `'potion'` で代用する書き方です（`Sheets.tsx:465`）。
- **直し方の案**: 「取り直しの時、シートは残すが、中の選択（渡す相手・開いた行）は消す」と決める。`coop-layers.mjs` に「行の枠を開いたまま切って戻す → 落ちない」を足す。小さなエラー境界（落ちたら「読み込み直す」ボタン）を足すかは【点検役の提案】。
- 知らせをシートの後ろへ回す件: 同行の誘い・「代わりに操作する」が見えなくなります。シートの見出しに押せない小さな印（「お知らせ 1」）を出すと、相方を待たせません【点検役の提案】。
- `visualViewport` を使う件: 文字入力のキーボードが出た時・指で拡大した時も値が変わります。「拡大していない時だけ」「キーボードの時は縮めない」の条件を書く。1人で遊ぶ時の全画面にも効く変更で、パソコンでは効き目を確かめられないので、**実機の確認の一覧**に入れる。

### F8（軽い）知らせの「8秒」と「15秒の猶予」の重なり

- `alive` に猶予を入れると、知らせ（`seatOnline` を見ている）は自動で5〜15秒遅れます。さらに8秒足すと、切れてから13〜28秒後。「代わりに操作」は35秒なので、知らせが出てすぐボタンが出る形になります。**猶予1つにまとめる**か、「8秒は接続の印が false になった時から数える（猶予とは別に足さない）」と書く。自分の「通信が切れました」の1行に8秒を当てるのかも書く。

### F9（軽い）bot の数字

- 2人以上の組の bot は、今「場面の先頭で払えるキャラ・フォーカス0」で挑みます（`bot.ts:580-587`）。案Aでは「いちばん得意なキャラ」になるので、イベントの成功が増え、その後の流れが変わります。乱数を引く回数は同じですが、**前に測った数字とは比べられなくなります**。計画書 §6 に「2人以上の bot の結果は変わる（人が遊ぶ難しさは同じ）」と書く。1人の bot は変わりません。

### F10（軽い）重なりの順番の表

- 今: シート z-50、転職のカード選び z-70、通信の知らせ z-70（`JobSheet.tsx:175`・`OnlineScreens.tsx:396`）。「シートをいちばん手前に」だけだと、転職のカード選び・確認の窓・物語・番の切り替えの演出との上下が決まりません。**層の表（下から順）を計画書に1つ**書いてから作ると、2人の作業者で食い違いません。
